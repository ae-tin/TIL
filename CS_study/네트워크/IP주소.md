# 2.4 IP 주소

## 학습 목표

이 단원에서는 네트워크에서 장치를 식별하고 데이터를 목적지까지 전달하는 데 사용되는 **IP 주소**를 학습한다.

학습 후 다음 내용을 설명할 수 있어야 한다.

* ARP가 필요한 이유
* IP 주소와 MAC 주소의 차이
* 홉바이홉 통신의 의미
* 라우터가 패킷을 전달하는 방식
* IPv4와 IPv6의 차이
* 공인 IP와 사설 IP의 차이
* 서브넷 마스크와 CIDR의 개념
* IP 주소 기반 위치 정보의 원리와 한계

---

# 2.4.1 ARP

## 1. ARP란?

**ARP**는 Address Resolution Protocol의 약자이다.
IP 주소를 MAC 주소로 변환하기 위해 사용하는 프로토콜이다.

네트워크 통신에서는 IP 주소와 MAC 주소가 모두 사용된다.

| 주소     | 사용 계층     | 역할                           |
| ------ | --------- | ---------------------------- |
| IP 주소  | 인터넷 계층    | 목적지 호스트를 찾기 위한 논리적 주소        |
| MAC 주소 | 데이터 링크 계층 | 같은 네트워크 안에서 장비를 찾기 위한 물리적 주소 |

즉, IP 주소는 “최종 목적지가 누구인가?”를 나타내고, MAC 주소는 “지금 이 네트워크 구간에서 누구에게 보낼 것인가?”를 나타낸다.

---

## 2. ARP가 필요한 이유

컴퓨터가 어떤 IP 주소로 데이터를 보내려면, 실제 Ethernet 프레임을 만들 때 목적지 MAC 주소가 필요하다.

예를 들어 내 PC가 같은 네트워크에 있는 `192.168.0.20`에게 데이터를 보내려고 한다고 하자.

내 PC는 목적지 IP 주소는 알고 있다.

```text id="wbeg80"
목적지 IP: 192.168.0.20
```

하지만 Ethernet 프레임을 만들려면 목적지 MAC 주소도 필요하다.

```text id="0m912e"
목적지 MAC: ?
```

이때 ARP를 사용한다.

---

## 3. ARP 동작 과정

ARP는 다음과 같은 방식으로 동작한다.

```text id="omtzlz"
1. 송신자가 목적지 IP에 대한 MAC 주소를 모름
2. ARP Request를 브로드캐스트로 전송
3. 해당 IP를 가진 장비가 ARP Reply로 자신의 MAC 주소를 응답
4. 송신자는 IP-MAC 매핑 정보를 ARP 캐시에 저장
5. 이후 통신에서는 ARP 캐시를 사용
```

---

## 4. ARP Request

ARP Request는 같은 네트워크에 있는 모든 장비에게 보내는 브로드캐스트 메시지이다.

```text id="tveyt0"
"192.168.0.20 쓰는 장비야, 네 MAC 주소가 뭐야?"
```

브로드캐스트 MAC 주소는 다음과 같다.

```text id="ytj0jp"
FF:FF:FF:FF:FF:FF
```

즉, 같은 LAN 안의 모든 장비가 이 요청을 받는다.

---

## 5. ARP Reply

요청받은 IP 주소를 가진 장비는 자신의 MAC 주소를 응답한다.

```text id="rr57tu"
"내가 192.168.0.20이고, 내 MAC 주소는 AA:BB:CC:DD:EE:FF야."
```

ARP Reply는 일반적으로 유니캐스트로 전송된다.

---

## 6. ARP 캐시

한 번 알아낸 IP-MAC 매핑 정보는 매번 다시 질의하지 않고 일정 시간 동안 저장한다.

이를 **ARP 캐시**라고 한다.

예시:

```text id="m2osdq"
192.168.0.1   →  00:11:22:33:44:55
192.168.0.20  →  AA:BB:CC:DD:EE:FF
```

ARP 캐시를 확인하는 명령어는 다음과 같다.

Windows:

```bash id="5icn8p"
arp -a
```

Linux/macOS:

```bash id="nw2mle"
arp -a
ip neigh
```

---

## 7. 같은 네트워크와 다른 네트워크에서의 ARP

ARP는 같은 네트워크 안에서 MAC 주소를 알아내기 위해 사용된다.

## 같은 네트워크에 목적지가 있는 경우

```text id="7ofqht"
내 PC: 192.168.0.10
목적지: 192.168.0.20
```

이 경우 내 PC는 목적지 IP `192.168.0.20`의 MAC 주소를 ARP로 찾는다.

```text id="6peg4x"
192.168.0.20의 MAC 주소가 뭐야?
```

---

## 다른 네트워크에 목적지가 있는 경우

```text id="bfcq0g"
내 PC: 192.168.0.10
목적지: 8.8.8.8
```

목적지 `8.8.8.8`은 같은 네트워크에 없다.
이 경우 내 PC는 `8.8.8.8`의 MAC 주소를 직접 찾지 않는다.

대신 기본 게이트웨이, 즉 공유기나 라우터의 MAC 주소를 ARP로 찾는다.

```text id="flxtqz"
기본 게이트웨이 192.168.0.1의 MAC 주소가 뭐야?
```

그 후 패킷은 라우터로 전달되고, 라우터가 다음 경로로 넘긴다.

---

## 8. ARP에서 중요한 점

IP 주소는 최종 목적지를 나타내지만, MAC 주소는 현재 네트워크 구간에서 다음 장비를 나타낸다.

예를 들어 외부 서버로 접속할 때 목적지 IP는 외부 서버 IP이다.

```text id="qq6fgw"
목적지 IP: 8.8.8.8
```

하지만 목적지 MAC 주소는 외부 서버의 MAC 주소가 아니라, 내 PC가 바로 보낼 수 있는 다음 장비의 MAC 주소이다.

```text id="ztq1x9"
목적지 MAC: 공유기 또는 다음 홉의 MAC 주소
```

---

## 9. ARP와 IPv6

ARP는 IPv4에서 사용하는 프로토콜이다.
IPv6에서는 ARP 대신 **NDP**, 즉 Neighbor Discovery Protocol을 사용한다.

| 구분       | IPv4 | IPv6    |
| -------- | ---- | ------- |
| 주소 변환 방식 | ARP  | NDP     |
| 브로드캐스트   | 사용   | 사용하지 않음 |
| 기반 프로토콜  | ARP  | ICMPv6  |

---

## 10. 면접 포인트

ARP는 IP 주소를 MAC 주소로 변환하기 위한 프로토콜이다.
같은 네트워크 안에서 목적지 장비의 MAC 주소를 알아내기 위해 사용된다.
다른 네트워크로 통신할 때는 최종 목적지의 MAC 주소를 찾는 것이 아니라, 기본 게이트웨이의 MAC 주소를 찾는다.

---

# 2.4.2 홉바이홉 통신

## 1. 홉이란?

**홉**은 패킷이 목적지까지 이동하는 과정에서 거치는 네트워크 장비 하나하나를 의미한다.

주로 라우터를 기준으로 홉을 세는 경우가 많다.

예를 들어 내 PC에서 어떤 웹 서버까지 가는 경로가 다음과 같다고 하자.

```text id="shzwmu"
내 PC → 공유기 → ISP 라우터 → 백본 라우터 → 웹 서버
```

이때 공유기, ISP 라우터, 백본 라우터 등이 각각 홉이 될 수 있다.

---

## 2. 홉바이홉 통신이란?

**홉바이홉 통신**은 패킷이 최종 목적지까지 한 번에 이동하는 것이 아니라, 다음 라우터를 거쳐가며 단계적으로 전달되는 방식을 의미한다.

즉, 각 라우터는 전체 경로를 모두 아는 것이 아니라, 다음으로 어디에 보내야 하는지만 판단한다.

```text id="f80ynv"
현재 장비 → 다음 홉 → 다음 홉 → 다음 홉 → 목적지
```

---

## 3. 라우터의 판단 방식

라우터는 패킷의 목적지 IP 주소를 확인하고, 자신의 라우팅 테이블을 조회한다.

```text id="y5vovi"
목적지 IP 확인
↓
라우팅 테이블 조회
↓
다음 홉 결정
↓
패킷 전달
```

라우터는 목적지 서버까지의 모든 상세 경로를 알 필요가 없다.
자신이 알고 있는 최적의 다음 홉으로만 패킷을 넘기면 된다.

---

## 4. 라우팅 테이블

라우팅 테이블은 목적지 네트워크에 따라 패킷을 어디로 보낼지 기록한 표이다.

예시:

| 목적지 네트워크       | 다음 홉        | 인터페이스 |
| -------------- | ----------- | ----- |
| 192.168.0.0/24 | 직접 연결       | eth0  |
| 10.0.0.0/8     | 192.168.0.1 | eth0  |
| 0.0.0.0/0      | 192.168.0.1 | eth0  |

여기서 `0.0.0.0/0`은 기본 경로를 의미한다.
명확히 일치하는 경로가 없을 때 기본 게이트웨이로 패킷을 보낸다.

---

## 5. 홉바이홉 통신에서 IP와 MAC 주소 변화

홉바이홉 통신에서 중요한 점은 다음과 같다.

```text id="ge7j8u"
IP 주소는 출발지와 목적지가 유지된다.
MAC 주소는 홉마다 바뀐다.
```

예를 들어 내 PC가 외부 서버 `8.8.8.8`로 패킷을 보낸다고 하자.

```text id="xiad4v"
출발지 IP: 내 PC IP
목적지 IP: 8.8.8.8
```

이 IP 정보는 일반적으로 목적지까지 유지된다.
단, NAT 환경에서는 출발지 IP가 변환될 수 있다.

반면 MAC 주소는 다음 홉으로 이동할 때마다 바뀐다.

```text id="z35dnq"
내 PC → 공유기
출발지 MAC: 내 PC MAC
목적지 MAC: 공유기 MAC

공유기 → ISP 라우터
출발지 MAC: 공유기 MAC
목적지 MAC: ISP 라우터 MAC

ISP 라우터 → 다음 라우터
출발지 MAC: ISP 라우터 MAC
목적지 MAC: 다음 라우터 MAC
```

즉, IP 주소는 종단 간 통신을 위한 주소이고, MAC 주소는 홉 단위 전달을 위한 주소이다.

---

## 6. TTL

**TTL**은 Time To Live의 약자이다.
패킷이 네트워크 안에서 무한히 떠도는 것을 방지하기 위한 값이다.

패킷이 라우터를 하나 지날 때마다 TTL 값은 1씩 감소한다.

```text id="z5j5jf"
TTL 64 → 라우터 통과 → TTL 63 → 라우터 통과 → TTL 62
```

TTL이 0이 되면 라우터는 해당 패킷을 폐기한다.

이 덕분에 잘못된 라우팅으로 인해 패킷이 무한 루프에 빠지는 것을 막을 수 있다.

---

## 7. traceroute와 홉

`traceroute` 또는 `tracert` 명령어는 목적지까지 가는 홉을 확인할 때 사용한다.

Linux/macOS:

```bash id="fpydaq"
traceroute google.com
```

Windows:

```bash id="13q36y"
tracert google.com
```

이 명령어는 TTL 값을 조절하면서 각 홉의 응답을 확인한다.

```text id="44d6tn"
1   192.168.0.1
2   ISP 라우터
3   백본 라우터
4   목적지 근처 라우터
```

이를 통해 어느 구간에서 지연이 발생하는지 분석할 수 있다.

---

## 8. 면접 포인트

홉바이홉 통신은 패킷이 최종 목적지까지 한 번에 가는 것이 아니라, 라우터를 거치며 다음 홉으로 전달되는 방식이다.
이 과정에서 목적지 IP 주소는 유지되지만, MAC 주소는 각 네트워크 구간마다 다음 홉의 MAC 주소로 바뀐다.

---

# 2.4.3 IP 주소 체계

## 1. IP 주소란?

**IP 주소**는 네트워크에서 장치를 식별하기 위한 논리적 주소이다.

IP 주소는 데이터를 목적지까지 전달하기 위해 사용된다.

```text id="d748gq"
IP 주소 = 네트워크에서 장치를 찾기 위한 주소
```

IP 주소에는 대표적으로 두 가지 버전이 있다.

| 구분   | 설명          |
| ---- | ----------- |
| IPv4 | 32비트 주소 체계  |
| IPv6 | 128비트 주소 체계 |

---

# IPv4

## 1. IPv4 주소

IPv4는 32비트 주소 체계이다.
보통 8비트씩 4개로 나누어 10진수로 표현한다.

예시:

```text id="62kd32"
192.168.0.1
8.8.8.8
```

각 부분은 0부터 255까지의 값을 가진다.

```text id="7jqk07"
192.168.0.1
= 11000000.10101000.00000000.00000001
```

---

## 2. IPv4 주소 개수

IPv4는 32비트이므로 이론적으로 만들 수 있는 주소 개수는 다음과 같다.

```text id="s72mlw"
2^32 = 약 43억 개
```

하지만 인터넷 사용 기기가 폭발적으로 증가하면서 IPv4 주소가 부족해졌다.
이 문제를 해결하기 위해 NAT, 사설 IP, IPv6 등이 사용된다.

---

## 3. 네트워크 부분과 호스트 부분

IP 주소는 크게 두 부분으로 나눌 수 있다.

```text id="a8p9h1"
네트워크 부분 + 호스트 부분
```

예를 들어 다음 IP 주소와 서브넷 마스크가 있다고 하자.

```text id="6rqnp9"
IP 주소: 192.168.0.10
서브넷 마스크: 255.255.255.0
```

이 경우 보통 다음과 같이 해석한다.

```text id="6svafc"
네트워크 부분: 192.168.0
호스트 부분: 10
```

같은 네트워크에 있는 장비들은 네트워크 부분이 같다.

---

## 4. 서브넷 마스크

**서브넷 마스크**는 IP 주소에서 어디까지가 네트워크 부분이고, 어디부터가 호스트 부분인지 구분하기 위한 값이다.

예시:

```text id="4dlwei"
IP 주소: 192.168.0.10
서브넷 마스크: 255.255.255.0
```

`255.255.255.0`은 앞의 24비트가 네트워크 부분이라는 뜻이다.

이를 CIDR 표기법으로 쓰면 다음과 같다.

```text id="7t4sh0"
192.168.0.10/24
```

---

## 5. CIDR

**CIDR**은 Classless Inter-Domain Routing의 약자이다.
IP 주소 뒤에 `/숫자`를 붙여 네트워크 부분의 길이를 표현한다.

예시:

| CIDR | 의미              |
| ---- | --------------- |
| /8   | 앞 8비트가 네트워크 부분  |
| /16  | 앞 16비트가 네트워크 부분 |
| /24  | 앞 24비트가 네트워크 부분 |
| /32  | 특정 호스트 하나       |

예를 들어 다음은 같은 네트워크 범위를 의미한다.

```text id="mcty2v"
192.168.0.0/24
```

이 네트워크는 일반적으로 다음 범위를 가진다.

```text id="ezl7zd"
네트워크 주소: 192.168.0.0
사용 가능한 호스트: 192.168.0.1 ~ 192.168.0.254
브로드캐스트 주소: 192.168.0.255
```

---

## 6. 네트워크 주소와 브로드캐스트 주소

## 네트워크 주소

네트워크 자체를 나타내는 주소이다.

```text id="tadpbu"
192.168.0.0/24에서 네트워크 주소 = 192.168.0.0
```

일반적으로 개별 장비에 할당하지 않는다.

---

## 브로드캐스트 주소

같은 네트워크에 있는 모든 장비에게 데이터를 보낼 때 사용하는 주소이다.

```text id="zw1mj3"
192.168.0.0/24에서 브로드캐스트 주소 = 192.168.0.255
```

---

## 7. 공인 IP와 사설 IP

## 공인 IP

공인 IP는 인터넷에서 직접 식별 가능한 IP 주소이다.
전 세계에서 유일해야 한다.

예시:

```text id="67hxq9"
8.8.8.8
1.1.1.1
```

공인 IP는 인터넷 서비스 제공자, 클라우드 사업자, 기관 등에 의해 할당된다.

---

## 사설 IP

사설 IP는 내부 네트워크에서만 사용하는 IP 주소이다.
인터넷에서는 직접 라우팅되지 않는다.

대표적인 사설 IP 대역은 다음과 같다.

| 대역             | 범위                            |
| -------------- | ----------------------------- |
| 10.0.0.0/8     | 10.0.0.0 ~ 10.255.255.255     |
| 172.16.0.0/12  | 172.16.0.0 ~ 172.31.255.255   |
| 192.168.0.0/16 | 192.168.0.0 ~ 192.168.255.255 |

가정에서 자주 보는 IP는 보통 사설 IP이다.

```text id="n71gxz"
192.168.0.2
192.168.1.10
10.0.0.5
```

---

## 8. NAT

**NAT**는 Network Address Translation의 약자이다.
사설 IP를 사용하는 내부 장비들이 하나의 공인 IP를 통해 인터넷에 접속할 수 있게 해준다.

예를 들어 집 안의 여러 기기가 모두 인터넷을 사용한다고 하자.

```text id="m5zuyg"
노트북: 192.168.0.10
스마트폰: 192.168.0.11
태블릿: 192.168.0.12
공유기 공인 IP: 203.0.113.10
```

외부 인터넷에서는 이 기기들이 모두 공유기의 공인 IP로 접속하는 것처럼 보인다.

NAT 덕분에 IPv4 주소 부족 문제를 완화할 수 있다.

---

## 9. DHCP

**DHCP**는 Dynamic Host Configuration Protocol의 약자이다.
네트워크에 접속한 장비에게 IP 주소를 자동으로 할당하는 프로토콜이다.

DHCP가 없다면 사용자가 직접 다음 정보를 설정해야 한다.

* IP 주소
* 서브넷 마스크
* 기본 게이트웨이
* DNS 서버

DHCP를 사용하면 공유기나 DHCP 서버가 이 정보를 자동으로 제공한다.

---

# IPv6

## 1. IPv6 주소

IPv6는 128비트 주소 체계이다.
IPv4 주소 부족 문제를 해결하기 위해 등장했다.

예시:

```text id="98rntw"
2001:0db8:85a3:0000:0000:8a2e:0370:7334
```

IPv6 주소는 16진수와 콜론을 사용해 표현한다.

---

## 2. IPv6의 특징

| 특징     | 설명            |
| ------ | ------------- |
| 주소 길이  | 128비트         |
| 주소 개수  | 사실상 매우 많음     |
| 표기 방식  | 16진수와 콜론 사용   |
| 브로드캐스트 | 없음            |
| 주소 변환  | ARP 대신 NDP 사용 |
| 보안성    | IPsec 지원 고려   |
| 자동 설정  | SLAAC 등 지원    |

---

## 3. IPv4와 IPv6 비교

| 구분      | IPv4        | IPv6        |
| ------- | ----------- | ----------- |
| 주소 길이   | 32비트        | 128비트       |
| 표기 예시   | 192.168.0.1 | 2001:db8::1 |
| 주소 개수   | 약 43억 개     | 매우 많음       |
| 주소 표현   | 10진수와 점     | 16진수와 콜론    |
| 브로드캐스트  | 있음          | 없음          |
| 주소 변환   | ARP         | NDP         |
| NAT 필요성 | 많이 사용       | 상대적으로 낮음    |

---

## 4. 특수 IP 주소

| 주소              | 의미                          |
| --------------- | --------------------------- |
| 127.0.0.1       | 로컬호스트, 자기 자신                |
| 0.0.0.0         | 모든 IPv4 주소 또는 아직 지정되지 않은 주소 |
| 255.255.255.255 | 제한 브로드캐스트 주소                |
| 169.254.0.0/16  | DHCP 실패 시 자동 할당되는 링크 로컬 주소  |
| ::1             | IPv6 로컬호스트                  |

---

## 5. 면접 포인트

IP 주소는 네트워크에서 장치를 식별하기 위한 논리적 주소이다.
IPv4는 32비트 주소 체계이고, IPv6는 128비트 주소 체계이다.
IPv4 주소 부족 문제를 완화하기 위해 사설 IP와 NAT가 사용되며, IPv6는 훨씬 넓은 주소 공간을 제공한다.

---

# 2.4.4 IP 주소를 이용한 위치 정보

## 1. IP 주소로 위치를 알 수 있는 이유

IP 주소는 인터넷 서비스 제공자, 통신사, 클라우드 사업자, 기업 등에 할당된다.
이 할당 정보와 네트워크 경로 정보를 이용하면 IP 주소가 어느 국가, 지역, 통신사에 속하는지 추정할 수 있다.

이를 **IP 지오로케이션**, 즉 IP 기반 위치 추정이라고 한다.

---

## 2. IP 위치 정보로 알 수 있는 것

IP 주소를 이용하면 보통 다음과 같은 정보를 추정할 수 있다.

* 국가
* 지역
* 도시
* 인터넷 서비스 제공자
* 조직명
* 시간대
* 대략적인 위도와 경도

예시:

```text id="a8fig1"
IP: 8.8.8.8
조직: Google
국가: 미국
용도: DNS 서버
```

---

## 3. IP 위치 정보의 활용

IP 기반 위치 정보는 여러 분야에서 사용된다.

| 활용 분야    | 설명                     |
| -------- | ---------------------- |
| 보안       | 의심스러운 국가나 지역의 접속 탐지    |
| 로그인 보호   | 평소와 다른 지역에서 접속 시 추가 인증 |
| 콘텐츠 제공   | 국가별 콘텐츠 제한 또는 언어 설정    |
| 광고       | 지역 기반 광고               |
| CDN      | 가까운 서버로 트래픽 분산         |
| 통계 분석    | 사용자 접속 지역 분석           |
| 부정 사용 탐지 | VPN, 프록시, 봇 접속 추정      |

---

## 4. IP 위치 정보의 한계

IP 주소만으로 사용자의 정확한 위치를 알 수는 없다.

이유는 다음과 같다.

## ISP 할당 위치와 실제 사용자 위치가 다를 수 있음

IP 주소는 통신사나 ISP 단위로 관리된다.
따라서 IP 주소의 등록 위치가 실제 사용자 위치와 다를 수 있다.

---

## 모바일 네트워크는 위치 오차가 클 수 있음

스마트폰의 LTE, 5G 네트워크는 트래픽이 통신사 장비를 거쳐 나가기 때문에 실제 사용자 위치와 다른 지역으로 표시될 수 있다.

---

## VPN과 프록시 사용

사용자가 VPN이나 프록시를 사용하면 실제 위치가 아닌 VPN 서버 위치로 보일 수 있다.

```text id="uxw5ew"
실제 위치: 서울
VPN 서버: 일본
IP 기반 위치: 일본
```

---

## 클라우드 서버 IP

AWS, GCP, Azure 같은 클라우드 IP는 데이터센터 위치나 사업자 등록 정보 기준으로 표시된다.
실제 서비스 사용자의 위치를 의미하지 않는다.

---

## NAT 환경

여러 사용자가 하나의 공인 IP를 공유할 수 있다.
따라서 하나의 IP가 반드시 한 명의 사용자를 의미하지 않는다.

---

## 5. IP 위치 정보와 GPS의 차이

| 구분        | IP 기반 위치        | GPS        |
| --------- | --------------- | ---------- |
| 기준        | 네트워크 할당 정보      | 위성 신호      |
| 정확도       | 낮거나 중간          | 높음         |
| 사용자 장치 필요 | IP만 있으면 가능      | GPS 센서 필요  |
| 오차 범위     | 도시, 지역 단위일 수 있음 | 수 미터 수준 가능 |
| VPN 영향    | 큼               | 상대적으로 작음   |

IP 위치 정보는 대략적인 지역 추정에 적합하고, GPS는 정확한 위치 측정에 적합하다.

---

## 6. IP 위치 정보 확인 방법

IP 위치 정보는 여러 웹 서비스나 API를 통해 확인할 수 있다.

또한 명령어로 현재 공인 IP를 확인할 수도 있다.

```bash id="g8r5eo"
curl ifconfig.me
```

또는 다음과 같이 확인할 수 있다.

```bash id="ni28rj"
curl ipinfo.io
```

단, IP 위치 정보 제공 서비스마다 데이터베이스가 다르기 때문에 결과가 다를 수 있다.

---

## 7. 면접 포인트

IP 주소 기반 위치 정보는 IP 주소 할당 정보와 네트워크 사업자 정보를 바탕으로 대략적인 위치를 추정하는 방식이다.
그러나 VPN, 프록시, NAT, 모바일 네트워크, 클라우드 환경 때문에 실제 사용자의 정확한 위치와 다를 수 있다.

---

# 전체 흐름 예시

내 PC가 외부 웹 서버에 접속하는 상황을 IP 주소 관점에서 정리하면 다음과 같다.

```text id="k9qkeu"
1. 사용자가 웹사이트 접속
2. DNS를 통해 도메인을 IP 주소로 변환
3. 목적지 IP가 같은 네트워크인지 확인
4. 다른 네트워크라면 기본 게이트웨이로 보낼 준비
5. ARP로 기본 게이트웨이의 MAC 주소 확인
6. Ethernet 프레임 생성
7. 라우터가 목적지 IP를 보고 다음 홉으로 전달
8. 여러 홉을 거쳐 목적지 서버 도착
9. 응답 패킷이 다시 클라이언트로 돌아옴
```

이때 핵심은 다음과 같다.

```text id="o5miox"
IP 주소: 최종 목적지 식별
MAC 주소: 현재 구간의 다음 장비 식별
라우터: 목적지 IP를 보고 다음 홉 결정
ARP: 같은 네트워크 안에서 IP를 MAC으로 변환
```

# 핵심 요약

## ARP

* ARP는 IP 주소를 MAC 주소로 변환하는 프로토콜이다.
* IPv4에서 사용된다.
* 같은 네트워크 안에서 목적지 장비의 MAC 주소를 알아낼 때 사용한다.
* 다른 네트워크로 보낼 때는 최종 목적지가 아니라 기본 게이트웨이의 MAC 주소를 찾는다.
* IPv6에서는 ARP 대신 NDP를 사용한다.

## 홉바이홉 통신

* 홉은 패킷이 거쳐가는 라우터나 네트워크 장비를 의미한다.
* 홉바이홉 통신은 패킷이 다음 홉을 거쳐 목적지까지 이동하는 방식이다.
* 라우터는 목적지 IP를 보고 다음 홉을 결정한다.
* IP 주소는 종단 간 통신에서 유지되고, MAC 주소는 홉마다 바뀐다.
* TTL은 패킷이 무한히 네트워크를 떠도는 것을 방지한다.

## IP 주소 체계

* IP 주소는 네트워크에서 장치를 식별하는 논리적 주소이다.
* IPv4는 32비트 주소 체계이다.
* IPv6는 128비트 주소 체계이다.
* 서브넷 마스크는 네트워크 부분과 호스트 부분을 구분한다.
* CIDR은 `/24`처럼 네트워크 부분의 길이를 표현한다.
* 공인 IP는 인터넷에서 직접 사용되는 주소이다.
* 사설 IP는 내부 네트워크에서만 사용하는 주소이다.
* NAT는 사설 IP를 공인 IP로 변환해 인터넷 통신을 가능하게 한다.

## IP 주소 기반 위치 정보

* IP 주소를 통해 국가, 지역, ISP, 조직 등을 추정할 수 있다.
* IP 위치 정보는 보안, 광고, CDN, 통계 분석 등에 활용된다.
* VPN, 프록시, NAT, 모바일 네트워크 때문에 정확도가 낮을 수 있다.
* IP 기반 위치 정보는 대략적인 위치 추정이고, GPS처럼 정확한 위치 정보는 아니다.

# 예상 질문

## Q1. ARP란 무엇인가요?

ARP는 IP 주소를 MAC 주소로 변환하기 위한 프로토콜입니다.
IPv4 환경에서 같은 네트워크 안의 장비에게 데이터를 보내기 위해 목적지 MAC 주소를 알아낼 때 사용합니다.

## Q2. 다른 네트워크에 있는 서버로 통신할 때 ARP는 어떤 MAC 주소를 찾나요?

최종 목적지 서버의 MAC 주소를 찾는 것이 아니라, 기본 게이트웨이의 MAC 주소를 찾습니다.
외부 네트워크로 나가는 패킷은 먼저 라우터나 공유기에게 전달되어야 하기 때문입니다.

## Q3. 홉바이홉 통신이란 무엇인가요?

패킷이 목적지까지 한 번에 이동하는 것이 아니라, 라우터를 거치며 다음 홉으로 단계적으로 전달되는 방식입니다.
각 라우터는 목적지 IP 주소를 보고 다음으로 보낼 장비를 결정합니다.

## Q4. 홉바이홉 통신에서 IP 주소와 MAC 주소는 어떻게 달라지나요?

목적지 IP 주소는 일반적으로 최종 목적지까지 유지됩니다.
반면 MAC 주소는 각 네트워크 구간에서 다음 홉 장비의 MAC 주소로 계속 바뀝니다.

## Q5. IPv4와 IPv6의 차이는 무엇인가요?

IPv4는 32비트 주소 체계이고, IPv6는 128비트 주소 체계입니다.
IPv4는 주소 개수가 제한적이어서 NAT와 사설 IP를 많이 사용하고, IPv6는 훨씬 많은 주소 공간을 제공합니다.

## Q6. 공인 IP와 사설 IP의 차이는 무엇인가요?

공인 IP는 인터넷에서 직접 식별 가능한 전 세계적으로 유일한 주소입니다.
사설 IP는 내부 네트워크에서만 사용하는 주소이며, 인터넷에 직접 라우팅되지 않습니다.

## Q7. NAT는 왜 필요한가요?

NAT는 사설 IP를 사용하는 내부 장비들이 하나의 공인 IP를 통해 인터넷에 접속할 수 있게 해줍니다.
이를 통해 IPv4 주소 부족 문제를 완화할 수 있습니다.

## Q8. CIDR이란 무엇인가요?

CIDR은 IP 주소 뒤에 `/숫자`를 붙여 네트워크 부분의 길이를 표현하는 방식입니다.
예를 들어 `192.168.0.0/24`는 앞의 24비트가 네트워크 부분이라는 뜻입니다.

## Q9. IP 주소로 정확한 위치를 알 수 있나요?

정확한 위치를 알 수는 없습니다.
IP 주소 기반 위치 정보는 ISP나 IP 할당 정보를 바탕으로 대략적인 지역을 추정하는 방식입니다.
VPN, 프록시, NAT, 모바일 네트워크를 사용하면 실제 위치와 다르게 표시될 수 있습니다.

---

# 암기용 한 줄 정리

* IP 주소는 네트워크에서 장치를 식별하는 논리적 주소이다.
* MAC 주소는 같은 네트워크 구간에서 장비를 식별하는 물리적 주소이다.
* ARP는 IPv4에서 IP 주소를 MAC 주소로 변환한다.
* 다른 네트워크로 보낼 때 ARP는 기본 게이트웨이의 MAC 주소를 찾는다.
* 홉은 패킷이 거쳐가는 네트워크 장비이다.
* 홉바이홉 통신은 패킷이 다음 홉을 거쳐 목적지까지 이동하는 방식이다.
* 라우터는 목적지 IP 주소를 보고 다음 홉을 결정한다.
* IP 주소는 종단 간 주소이고, MAC 주소는 홉 단위 주소이다.
* IPv4는 32비트, IPv6는 128비트 주소 체계이다.
* 공인 IP는 인터넷에서 직접 사용되고, 사설 IP는 내부망에서 사용된다.
* NAT는 사설 IP와 공인 IP를 변환한다.
* CIDR은 `/24`처럼 네트워크 부분의 길이를 표현한다.
* IP 위치 정보는 대략적인 추정이며 정확한 실제 위치가 아니다.
