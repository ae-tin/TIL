# 2.1 네트워크의 기초

## 학습 목표

이 단원에서는 네트워크의 기본 개념을 이해하고, 네트워크 성능을 판단하는 핵심 지표와 구조, 분류 방식, 분석 명령어, 프로토콜 표준화의 필요성을 학습한다.

학습 후 다음 내용을 설명할 수 있어야 한다.

* 처리량과 지연 시간의 차이
* 네트워크 토폴로지의 종류와 병목 현상
* LAN, MAN, WAN 등 네트워크 분류
* `ping`, `traceroute`, `netstat`, `nslookup` 등 기본 분석 명령어
* 네트워크 프로토콜 표준화가 필요한 이유

---

# 2.1.1 처리량과 지연 시간

## 1. 처리량

**처리량**은 일정 시간 동안 네트워크를 통해 실제로 전달된 데이터의 양을 의미한다.

보통 단위는 다음과 같다.

* bps: bits per second
* Kbps
* Mbps
* Gbps

예를 들어, 1초 동안 100Mb의 데이터가 전송되었다면 처리량은 `100Mbps`이다.

## 2. 대역폭과 처리량의 차이

대역폭과 처리량은 비슷해 보이지만 다르다.

| 구분  | 의미                          |
| --- | --------------------------- |
| 대역폭 | 네트워크가 이론적으로 감당할 수 있는 최대 전송량 |
| 처리량 | 실제로 전송된 데이터량                |

예를 들어, 인터넷 상품이 `1Gbps`라고 해도 실제 다운로드 속도가 항상 1Gbps가 나오는 것은 아니다.
네트워크 혼잡, 서버 상태, 장비 성능, 거리, 패킷 손실 등의 영향으로 실제 처리량은 낮아질 수 있다.

```text
대역폭: 도로의 차선 수
처리량: 실제로 도로를 지나간 차량 수
```

## 3. 지연 시간

**지연 시간**은 데이터가 출발지에서 목적지까지 도달하는 데 걸리는 시간을 의미한다.

보통 단위는 다음과 같다.

* ms: millisecond
* 1ms = 0.001초

지연 시간은 다음 요소들로 구성된다.

| 요소    | 설명                      |
| ----- | ----------------------- |
| 전송 지연 | 데이터를 링크에 밀어 넣는 데 걸리는 시간 |
| 전파 지연 | 신호가 물리적 매체를 따라 이동하는 시간  |
| 처리 지연 | 라우터, 스위치 등이 패킷을 처리하는 시간 |
| 큐잉 지연 | 네트워크 장비의 큐에서 대기하는 시간    |

## 4. 처리량과 지연 시간의 관계

처리량이 높다고 해서 지연 시간이 항상 낮은 것은 아니다.

예를 들어, 파일 다운로드에서는 처리량이 중요하다.
반면 온라인 게임, 화상 회의, 실시간 음성 통화에서는 지연 시간이 더 중요하다.

| 상황          | 중요한 지표           |
| ----------- | ---------------- |
| 대용량 파일 다운로드 | 처리량              |
| 온라인 게임      | 지연 시간            |
| 화상 회의       | 지연 시간, 패킷 손실     |
| 스트리밍        | 처리량, 지연 시간       |
| 웹 페이지 로딩    | 지연 시간, 처리량 모두 중요 |

## 5. 면접 포인트

처리량은 실제로 전송된 데이터의 양이고, 지연 시간은 데이터가 목적지까지 도달하는 데 걸리는 시간이다.
대역폭이 높아도 네트워크 혼잡, 패킷 손실, 서버 상태 등에 따라 실제 처리량은 낮아질 수 있다.

# 2.1.2 네트워크 토폴로지와 병목 현상

## 1. 네트워크 토폴로지

**네트워크 토폴로지**는 노드와 링크가 어떻게 연결되어 있는지를 나타내는 네트워크의 구조이다.

여기서 노드는 컴퓨터, 서버, 라우터, 스위치 같은 장비를 의미하고, 링크는 장비 간 연결을 의미한다.

## 2. 주요 토폴로지 종류

## 버스형 토폴로지

모든 장비가 하나의 중앙 통신 회선에 연결된 구조이다.

```text
PC ─ PC ─ PC ─ PC ─ PC
```

### 장점

* 구조가 단순하다.
* 설치 비용이 비교적 낮다.

### 단점

* 중앙 회선에 문제가 생기면 전체 네트워크에 장애가 발생할 수 있다.
* 트래픽이 많아지면 충돌이 증가한다.

---

## 스타형 토폴로지

중앙 장비를 기준으로 여러 노드가 연결되는 구조이다.

```text
      PC
       |
PC ─ Switch ─ PC
       |
      PC
```

### 장점

* 관리가 쉽다.
* 특정 노드에 문제가 생겨도 전체 네트워크에 미치는 영향이 작다.

### 단점

* 중앙 장비에 장애가 발생하면 전체 네트워크가 영향을 받는다.
* 중앙 장비에 트래픽이 집중될 수 있다.

---

## 링형 토폴로지

각 노드가 양 옆의 노드와 연결되어 고리 형태를 이루는 구조이다.

```text
PC ─ PC
|     |
PC ─ PC
```

### 장점

* 데이터 흐름이 일정하다.
* 충돌 가능성이 낮다.

### 단점

* 한 노드나 링크에 장애가 생기면 전체 네트워크에 영향을 줄 수 있다.
* 구조 변경이 어렵다.

---

## 메시형 토폴로지

여러 노드가 서로 복잡하게 연결된 구조이다.

```text
PC ─── PC
|\    /|
| \  / |
|  \/  |
|  /\  |
| /  \ |
|/    \|
PC ─── PC
```

### 장점

* 장애에 강하다.
* 특정 경로가 끊겨도 다른 경로로 통신할 수 있다.

### 단점

* 구축 비용이 높다.
* 관리가 복잡하다.

---

## 트리형 토폴로지

계층 구조를 가진 토폴로지이다.

```text
        Core
       /    \
   Switch  Switch
    /  \     /  \
  PC   PC  PC   PC
```

### 장점

* 확장성이 좋다.
* 계층적으로 관리하기 쉽다.

### 단점

* 상위 계층 장비에 장애가 발생하면 하위 네트워크가 영향을 받는다.

---

## 3. 병목 현상

**병목 현상**은 전체 시스템의 성능이 특정 지점의 한계 때문에 제한되는 현상이다.

네트워크에서는 다음과 같은 부분에서 병목이 발생할 수 있다.

* 라우터
* 스위치
* 서버
* 네트워크 회선
* 방화벽
* 데이터베이스
* DNS 서버
* 애플리케이션 서버

## 4. 병목 현상 예시

사용자가 웹 서비스를 이용한다고 가정하자.

```text
사용자 → 공유기 → 인터넷 → 로드밸런서 → 웹 서버 → DB 서버
```

이때 웹 서버는 충분히 빠르더라도 DB 서버 응답이 느리면 전체 서비스는 느려진다.
이 경우 병목 지점은 DB 서버이다.

## 5. 병목 현상 해결 방법

| 원인           | 해결 방법              |
| ------------ | ------------------ |
| 서버 성능 부족     | 스케일 업, 스케일 아웃      |
| 네트워크 대역폭 부족  | 회선 증설              |
| DB 응답 지연     | 인덱스 최적화, 쿼리 개선, 캐싱 |
| 특정 서버 트래픽 집중 | 로드밸런싱              |
| 패킷 손실        | 네트워크 장비 점검         |
| DNS 지연       | DNS 캐싱, DNS 서버 변경  |

## 6. 면접 포인트

네트워크 병목은 단순히 인터넷 속도 문제만 의미하지 않는다.
클라이언트에서 서버까지 이어지는 전체 경로 중 가장 느린 지점이 전체 성능을 제한한다.

# 2.1.3 네트워크 분류

네트워크는 규모, 연결 방식, 사용 목적 등에 따라 여러 방식으로 분류할 수 있다.

---

## 1. 규모에 따른 분류

## PAN

**PAN**은 Personal Area Network의 약자이다.
개인 주변 장치 간의 네트워크를 의미한다.

예시:

* 블루투스 이어폰
* 스마트워치
* 무선 마우스
* 스마트폰 테더링

---

## LAN

**LAN**은 Local Area Network의 약자이다.
가정, 학교, 회사, 사무실처럼 비교적 좁은 범위의 네트워크를 의미한다.

예시:

* 집 안의 와이파이
* 회사 내부 네트워크
* 학교 전산실 네트워크

특징:

* 속도가 빠르다.
* 관리 범위가 좁다.
* 일반적으로 사설 IP를 사용한다.

---

## MAN

**MAN**은 Metropolitan Area Network의 약자이다.
도시 규모의 네트워크를 의미한다.

예시:

* 도시 단위 공공 와이파이
* 지역 케이블망
* 대학교 캠퍼스 간 연결망

---

## WAN

**WAN**은 Wide Area Network의 약자이다.
국가, 대륙, 전 세계처럼 넓은 범위를 연결하는 네트워크이다.

대표적인 예시는 인터넷이다.

특징:

* 범위가 매우 넓다.
* 여러 LAN과 MAN이 연결되어 구성된다.
* 통신사, 해저 케이블, 백본망 등이 관여한다.

---

## 2. 연결 방식에 따른 분류

## 유선 네트워크

케이블을 사용하여 장비를 연결하는 네트워크이다.

예시:

* 이더넷
* 광케이블
* 동축 케이블

장점:

* 안정적이다.
* 속도가 빠르다.
* 간섭이 적다.

단점:

* 설치가 번거롭다.
* 이동성이 낮다.

---

## 무선 네트워크

전파를 이용하여 장비를 연결하는 네트워크이다.

예시:

* Wi-Fi
* Bluetooth
* LTE
* 5G

장점:

* 이동성이 좋다.
* 설치가 편리하다.

단점:

* 간섭에 취약하다.
* 유선보다 안정성이 낮을 수 있다.
* 보안 설정이 중요하다.

---

## 3. 사용 목적에 따른 분류

## 인터넷

전 세계적으로 연결된 공개 네트워크이다.

## 인트라넷

조직 내부에서만 사용하는 사설 네트워크이다.

예시:

* 회사 내부 업무 시스템
* 사내 게시판
* 내부 문서 시스템

## 엑스트라넷

외부 협력사나 특정 사용자에게 제한적으로 접근을 허용하는 네트워크이다.

예시:

* 협력사 전용 발주 시스템
* 파트너사 전용 관리 페이지

---

## 4. 구조에 따른 분류

## 클라이언트-서버 구조

서버가 서비스를 제공하고 클라이언트가 요청하는 구조이다.

```text
Client → Server
Client → Server
Client → Server
```

예시:

* 웹 서비스
* 이메일
* 온라인 쇼핑몰
* 은행 앱

장점:

* 중앙 관리가 쉽다.
* 보안 정책 적용이 쉽다.

단점:

* 서버에 부하가 집중된다.
* 서버 장애 시 서비스 전체에 영향이 크다.

---

## P2P 구조

각 노드가 클라이언트이면서 동시에 서버 역할을 하는 구조이다.

```text
Node ↔ Node ↔ Node
  ↖        ↗
     Node
```

예시:

* 파일 공유
* 블록체인 네트워크
* 일부 메신저 구조

장점:

* 특정 서버에 의존하지 않는다.
* 확장성이 좋을 수 있다.

단점:

* 관리가 어렵다.
* 보안과 신뢰성 문제가 발생할 수 있다.

---

# 2.1.4 네트워크 성능 분석 명령어

네트워크 문제가 발생했을 때는 명령어를 사용해 원인을 분석할 수 있다.

---

## 1. ping

`ping`은 특정 호스트와 통신이 가능한지 확인하는 명령어이다.

```bash
ping google.com
```

확인할 수 있는 것:

* 대상 서버가 응답하는지
* 왕복 시간, 즉 RTT가 얼마나 되는지
* 패킷 손실이 있는지

예시 결과:

```text
64 bytes from 142.250.207.14: icmp_seq=1 ttl=116 time=32.5 ms
```

여기서 `time=32.5 ms`는 패킷이 목적지까지 갔다가 다시 돌아오는 데 걸린 시간이다.

## 2. traceroute / tracert

`traceroute`는 목적지까지 가는 경로를 확인하는 명령어이다.

Linux, macOS:

```bash
traceroute google.com
```

Windows:

```bash
tracert google.com
```

확인할 수 있는 것:

* 패킷이 거쳐 가는 라우터 목록
* 어느 구간에서 지연이 발생하는지
* 특정 구간에서 패킷이 막히는지

예시 흐름:

```text
내 PC → 공유기 → ISP 라우터 → 백본망 → 목적지 서버
```

## 3. nslookup

`nslookup`은 도메인 이름이 어떤 IP 주소로 해석되는지 확인하는 명령어이다.

```bash
nslookup google.com
```

확인할 수 있는 것:

* DNS가 정상 동작하는지
* 도메인이 어떤 IP로 연결되는지
* DNS 서버 응답에 문제가 있는지

## 4. dig

`dig`는 DNS 정보를 더 자세히 확인할 수 있는 명령어이다.

```bash
dig google.com
```

특정 레코드를 조회할 수도 있다.

```bash
dig google.com A
dig google.com MX
dig google.com TXT
```

주요 DNS 레코드:

| 레코드   | 의미                  |
| ----- | ------------------- |
| A     | 도메인을 IPv4 주소로 매핑    |
| AAAA  | 도메인을 IPv6 주소로 매핑    |
| CNAME | 다른 도메인 이름으로 별칭 지정   |
| MX    | 메일 서버 정보            |
| TXT   | 텍스트 정보, 인증 정보 등에 사용 |

## 5. netstat

`netstat`은 현재 네트워크 연결 상태를 확인하는 명령어이다.

```bash
netstat -an
```

확인할 수 있는 것:

* 열려 있는 포트
* 현재 연결된 IP와 포트
* TCP 연결 상태

TCP 상태 예시:

| 상태          | 의미                 |
| ----------- | ------------------ |
| LISTEN      | 연결 요청을 기다리는 상태     |
| ESTABLISHED | 연결이 수립된 상태         |
| TIME_WAIT   | 연결 종료 후 대기 상태      |
| CLOSE_WAIT  | 상대방이 연결 종료를 요청한 상태 |

## 6. ss

`ss`는 Linux에서 `netstat`보다 빠르게 소켓 정보를 확인할 수 있는 명령어이다.

```bash
ss -tuln
```

옵션 의미:

| 옵션 | 의미            |
| -- | ------------- |
| -t | TCP           |
| -u | UDP           |
| -l | Listening 상태  |
| -n | 포트 번호를 숫자로 표시 |

## 7. ipconfig / ifconfig / ip

IP 설정 정보를 확인하는 명령어이다.

Windows:

```bash
ipconfig
```

Linux, macOS:

```bash
ifconfig
```

Linux 최신 환경:

```bash
ip addr
```

확인할 수 있는 것:

* IP 주소
* 서브넷 마스크
* 기본 게이트웨이
* 네트워크 인터페이스 정보

## 8. curl

`curl`은 HTTP 요청을 보내 서버 응답을 확인하는 명령어이다.

```bash
curl https://example.com
```

헤더만 확인하고 싶을 때:

```bash
curl -I https://example.com
```

응답 시간까지 확인하고 싶을 때:

```bash
curl -w "%{time_total}\n" -o /dev/null -s https://example.com
```

확인할 수 있는 것:

* 서버가 정상 응답하는지
* HTTP 상태 코드
* 응답 헤더
* 응답 시간

## 9. tcpdump

`tcpdump`는 네트워크 패킷을 캡처하는 명령어이다.

```bash
sudo tcpdump -i eth0
```

특정 포트만 확인할 수도 있다.

```bash
sudo tcpdump -i eth0 port 80
```

확인할 수 있는 것:

* 실제 패킷이 오가는지
* 특정 포트로 통신이 발생하는지
* TCP handshake가 정상적으로 이루어지는지

# 2.1.5 네트워크 프로토콜 표준화

## 1. 프로토콜이란?

**프로토콜**은 네트워크에서 데이터를 주고받기 위한 규칙이다.

사람이 대화할 때 언어와 문법이 필요한 것처럼, 컴퓨터끼리 통신할 때도 정해진 규칙이 필요하다.

예를 들어 웹 브라우저가 서버에 요청을 보낼 때는 HTTP라는 프로토콜을 사용한다.

```text
브라우저 → HTTP 요청 → 웹 서버
브라우저 ← HTTP 응답 ← 웹 서버
```

## 2. 프로토콜이 필요한 이유

네트워크에는 다양한 장비와 운영체제, 애플리케이션이 존재한다.

예를 들어 다음 장비들이 서로 통신해야 한다.

* Windows PC
* MacBook
* Linux 서버
* Android 스마트폰
* iPhone
* Cisco 라우터
* AWS 서버

이들이 각자 다른 방식으로 통신하면 서로 데이터를 이해할 수 없다.
따라서 공통된 통신 규칙이 필요하다.

## 3. 표준화란?

**표준화**는 서로 다른 시스템이 같은 규칙을 따르도록 공통 기준을 정하는 것이다.

네트워크 프로토콜이 표준화되어 있기 때문에 서로 다른 제조사의 장비와 서로 다른 운영체제의 컴퓨터가 통신할 수 있다.

## 4. 대표적인 네트워크 프로토콜

| 프로토콜        | 역할                 |
| ----------- | ------------------ |
| IP          | 목적지 주소를 기반으로 패킷 전달 |
| TCP         | 신뢰성 있는 데이터 전송      |
| UDP         | 빠른 데이터 전송          |
| HTTP        | 웹 요청과 응답           |
| HTTPS       | 암호화된 웹 통신          |
| DNS         | 도메인 이름을 IP 주소로 변환  |
| DHCP        | IP 주소 자동 할당        |
| FTP         | 파일 전송              |
| SMTP        | 이메일 전송             |
| POP3 / IMAP | 이메일 수신             |
| SSH         | 원격 서버 접속           |

## 5. TCP와 UDP 비교

| 구분    | TCP           | UDP             |
| ----- | ------------- | --------------- |
| 연결 방식 | 연결 지향         | 비연결 지향          |
| 신뢰성   | 높음            | 낮음              |
| 속도    | 상대적으로 느림      | 상대적으로 빠름        |
| 순서 보장 | 보장            | 보장하지 않음         |
| 재전송   | 있음            | 없음              |
| 사용 예시 | 웹, 이메일, 파일 전송 | 스트리밍, 게임, 음성 통화 |

TCP는 안정성이 중요한 상황에서 사용된다.
UDP는 속도와 실시간성이 중요한 상황에서 사용된다.

## 6. HTTP와 HTTPS

HTTP는 웹에서 클라이언트와 서버가 데이터를 주고받기 위한 프로토콜이다.

HTTPS는 HTTP에 보안 계층을 추가한 프로토콜이다.

| 구분    | HTTP    | HTTPS            |
| ----- | ------- | ---------------- |
| 보안    | 암호화 없음  | 암호화 적용           |
| 기본 포트 | 80      | 443              |
| 사용 예시 | 일반 웹 통신 | 로그인, 결제, 개인정보 처리 |

## 7. 표준화 기구

네트워크 표준은 여러 국제 기구를 통해 관리된다.

| 기구    | 역할                     |
| ----- | ---------------------- |
| IEEE  | 이더넷, Wi-Fi 등 LAN 관련 표준 |
| IETF  | 인터넷 프로토콜 표준            |
| ISO   | OSI 7계층 모델 등 국제 표준     |
| W3C   | 웹 표준                   |
| ICANN | 도메인 이름과 IP 주소 관리       |

## 8. 표준화의 장점

프로토콜 표준화의 장점은 다음과 같다.

* 서로 다른 장비 간 호환성 확보
* 네트워크 확장성 증가
* 장애 분석과 유지보수 용이
* 보안 정책 적용 용이
* 개발자와 제조사 간 공통 기준 제공

## 9. 면접 포인트

프로토콜은 네트워크 통신 규칙이고, 표준화는 서로 다른 시스템이 같은 규칙으로 통신할 수 있게 만드는 과정이다.
표준화 덕분에 제조사, 운영체제, 장비가 달라도 인터넷 통신이 가능하다.

# 핵심 요약

## 처리량과 지연 시간

* 처리량은 일정 시간 동안 실제로 전송된 데이터의 양이다.
* 지연 시간은 데이터가 목적지까지 도달하는 데 걸리는 시간이다.
* 대역폭이 높아도 실제 처리량은 낮을 수 있다.
* 실시간 서비스에서는 지연 시간이 특히 중요하다.

## 네트워크 토폴로지와 병목 현상

* 토폴로지는 네트워크 장비들이 연결된 구조이다.
* 대표적인 토폴로지는 버스형, 스타형, 링형, 메시형, 트리형이다.
* 병목 현상은 전체 성능이 특정 지점의 한계로 제한되는 현상이다.
* 병목은 서버, DB, 라우터, 회선, DNS 등 다양한 지점에서 발생할 수 있다.

## 네트워크 분류

* PAN: 개인 주변 장치 네트워크
* LAN: 가정, 회사, 학교 등 좁은 범위의 네트워크
* MAN: 도시 규모 네트워크
* WAN: 국가 또는 전 세계 규모 네트워크
* 인터넷은 대표적인 WAN이다.

## 네트워크 성능 분석 명령어

* `ping`: 연결 가능 여부와 RTT 확인
* `traceroute`, `tracert`: 목적지까지의 경로 확인
* `nslookup`, `dig`: DNS 조회
* `netstat`, `ss`: 포트와 연결 상태 확인
* `ipconfig`, `ifconfig`, `ip addr`: IP 설정 확인
* `curl`: HTTP 응답 확인
* `tcpdump`: 패킷 캡처

## 네트워크 프로토콜 표준화

* 프로토콜은 네트워크 통신 규칙이다.
* 표준화는 서로 다른 시스템이 같은 방식으로 통신하게 만드는 과정이다.
* 대표적인 프로토콜에는 IP, TCP, UDP, HTTP, HTTPS, DNS, DHCP, SSH 등이 있다.

# 예상 질문

## Q1. 처리량과 대역폭의 차이는 무엇인가요?

대역폭은 네트워크가 이론적으로 처리할 수 있는 최대 전송량이고, 처리량은 실제로 전송된 데이터의 양입니다.
대역폭이 높아도 네트워크 혼잡, 서버 성능, 패킷 손실 등의 이유로 실제 처리량은 낮아질 수 있습니다.

## Q2. 지연 시간이 중요한 서비스는 무엇인가요?

온라인 게임, 화상 회의, 음성 통화, 실시간 스트리밍처럼 즉각적인 반응이 필요한 서비스에서 지연 시간이 중요합니다.

## Q3. 스타형 토폴로지의 장단점은 무엇인가요?

스타형 토폴로지는 중앙 장비를 기준으로 여러 노드가 연결되는 구조입니다.
관리가 쉽고 특정 노드 장애가 전체에 미치는 영향은 작지만, 중앙 장비에 장애가 발생하면 전체 네트워크가 영향을 받을 수 있습니다.

## Q4. 병목 현상이란 무엇인가요?

병목 현상은 전체 시스템의 성능이 특정 지점의 한계 때문에 제한되는 현상입니다.
네트워크에서는 서버, DB, 라우터, 스위치, 회선, DNS 등 다양한 위치에서 병목이 발생할 수 있습니다.

## Q5. LAN과 WAN의 차이는 무엇인가요?

LAN은 집, 회사, 학교처럼 좁은 범위의 네트워크이고, WAN은 국가나 전 세계처럼 넓은 범위의 네트워크입니다.
인터넷은 대표적인 WAN입니다.

## Q6. ping과 traceroute의 차이는 무엇인가요?

`ping`은 목적지와 통신이 가능한지와 왕복 시간을 확인하는 명령어입니다.
`traceroute`는 목적지까지 패킷이 어떤 경로를 거쳐 가는지 확인하는 명령어입니다.

## Q7. DNS 문제를 확인할 때 어떤 명령어를 사용할 수 있나요?

`nslookup`이나 `dig`를 사용할 수 있습니다.
이 명령어들은 도메인 이름이 어떤 IP 주소로 해석되는지 확인하는 데 사용됩니다.

## Q8. TCP와 UDP의 차이는 무엇인가요?

TCP는 연결 지향적이고 신뢰성을 보장하는 프로토콜입니다.
UDP는 비연결 지향적이고 신뢰성은 낮지만 빠른 전송에 적합합니다.
TCP는 웹, 이메일, 파일 전송에 사용되고 UDP는 스트리밍, 게임, 음성 통화 등에 사용됩니다.

## Q9. 프로토콜 표준화가 필요한 이유는 무엇인가요?

서로 다른 제조사의 장비와 서로 다른 운영체제를 사용하는 컴퓨터들이 동일한 규칙으로 통신하기 위해 필요합니다.
표준화가 되어 있기 때문에 Windows, Linux, macOS, 스마트폰, 서버, 라우터 등이 서로 통신할 수 있습니다.
