# 2.3 네트워크 기기

## 학습 목표

이 단원에서는 네트워크 기기가 어떤 계층의 정보를 기준으로 데이터를 처리하는지 학습한다.

네트워크 장비는 모두 같은 방식으로 동작하지 않는다.
어떤 장비는 전기 신호만 증폭하고, 어떤 장비는 MAC 주소를 보고 전달하며, 어떤 장비는 IP 주소나 HTTP 요청 내용까지 분석한다.

학습 후 다음 내용을 설명할 수 있어야 한다.

* 네트워크 기기의 계층별 처리 범위
* 상위 계층 장비와 하위 계층 장비의 차이
* L7 스위치와 L4 스위치의 차이
* 라우터와 L3 스위치의 역할
* L2 스위치와 브리지의 역할
* NIC, 리피터, AP의 역할
* 각 장비가 어떤 주소나 정보를 기준으로 동작하는지

---

# 2.3.1 네트워크 기기의 처리 범위

## 1. 네트워크 기기와 계층

네트워크 기기는 자신이 처리하는 계층에 따라 분류할 수 있다.

```text id="muua2q"
애플리케이션 계층: L7 스위치
전송 계층: L4 스위치
인터넷 계층: 라우터, L3 스위치
데이터 링크 계층: L2 스위치, 브리지
물리 계층: NIC, 리피터, AP
```

여기서 중요한 점은 **상위 계층을 처리하는 장비는 하위 계층의 기능도 함께 처리할 수 있다**는 것이다.

예를 들어 L7 스위치는 HTTP 요청 내용을 볼 수 있지만, 실제 통신을 위해 IP, 포트, MAC 주소 정보도 함께 다룰 수 있다.

반대로 L2 스위치는 MAC 주소까지만 보고 동작하므로 HTTP 요청 내용이나 IP 라우팅 정책을 이해하지 못한다.

---

## 2. 계층별 처리 정보

| 계층        | 장비 예시        | 주로 보는 정보                |
| --------- | ------------ | ----------------------- |
| 애플리케이션 계층 | L7 스위치       | URL, HTTP 헤더, 쿠키, 요청 경로 |
| 전송 계층     | L4 스위치       | IP 주소, 포트 번호, TCP/UDP   |
| 인터넷 계층    | 라우터, L3 스위치  | IP 주소                   |
| 데이터 링크 계층 | L2 스위치, 브리지  | MAC 주소                  |
| 물리 계층     | NIC, 리피터, AP | 전기 신호, 광 신호, 무선 신호      |

---

## 3. 상위 계층 장비와 하위 계층 장비

상위 계층 장비는 더 많은 정보를 분석할 수 있다.

예를 들어 사용자가 다음과 같은 HTTP 요청을 보냈다고 하자.

```http id="j3qpm1"
GET /api/users HTTP/1.1
Host: example.com
Cookie: session_id=abc123
```

L7 스위치는 다음 정보를 볼 수 있다.

* 요청 URL
* 요청 경로
* HTTP 메서드
* 헤더
* 쿠키
* 콘텐츠 타입

반면 L3 장비인 라우터는 HTTP 요청의 내용을 보지 않고, 목적지 IP 주소를 기준으로 패킷을 전달한다.

L2 스위치는 IP 주소도 핵심 기준으로 보지 않고, MAC 주소를 기준으로 프레임을 전달한다.

---

## 4. 계층별 장비를 이해하는 핵심 기준

네트워크 기기를 이해할 때는 다음 질문을 던지면 된다.

```text id="xy0wgm"
이 장비는 어떤 정보를 보고 판단하는가?
```

예를 들어 다음과 같이 정리할 수 있다.

| 장비     | 판단 기준         |
| ------ | ------------- |
| L7 스위치 | HTTP 요청 내용    |
| L4 스위치 | IP 주소 + 포트 번호 |
| 라우터    | IP 주소         |
| L2 스위치 | MAC 주소        |
| 리피터    | 신호 자체         |

---

# 2.3.2 애플리케이션 계층을 처리하는 기기

## 1. L7 스위치

애플리케이션 계층을 처리하는 대표적인 기기는 **L7 스위치**이다.

L7 스위치는 OSI 7계층 중 애플리케이션 계층의 정보를 보고 트래픽을 처리하는 장비이다.
실무에서는 보통 **애플리케이션 로드밸런서**라고도 부른다.

---

## 2. L7 스위치가 보는 정보

L7 스위치는 단순히 IP와 포트만 보는 것이 아니라, 애플리케이션 요청 내용을 분석한다.

예를 들어 HTTP 요청에서 다음 정보를 확인할 수 있다.

* URL
* URI
* HTTP 메서드
* HTTP 헤더
* 쿠키
* 요청 본문 일부
* 콘텐츠 타입
* 호스트명
* 경로

예시:

```http id="s2g62y"
GET /api/orders HTTP/1.1
Host: shop.example.com
Cookie: user_type=premium
```

L7 스위치는 이 요청을 보고 다음과 같은 처리를 할 수 있다.

```text id="ktxjy9"
/api/orders 요청 → 주문 서버로 전달
/api/users 요청 → 사용자 서버로 전달
/static 요청 → 정적 파일 서버로 전달
```

---

## 3. L7 스위치의 주요 역할

## 로드밸런싱

여러 서버에 요청을 분산한다.

```text id="r923d6"
Client
  ↓
L7 Switch
  ↓      ↓      ↓
Web1   Web2   Web3
```

특정 서버에만 트래픽이 몰리지 않도록 분산하여 안정성을 높인다.

---

## URL 기반 라우팅

요청 경로에 따라 다른 서버로 전달할 수 있다.

| 요청 경로         | 전달 서버         |
| ------------- | ------------- |
| `/api/users`  | User Server   |
| `/api/orders` | Order Server  |
| `/images`     | Static Server |
| `/admin`      | Admin Server  |

---

## 호스트 기반 라우팅

도메인에 따라 다른 서비스로 전달할 수 있다.

| Host                 | 전달 서버         |
| -------------------- | ------------- |
| `api.example.com`    | API Server    |
| `admin.example.com`  | Admin Server  |
| `static.example.com` | Static Server |

---

## SSL/TLS 종료

HTTPS 요청을 L7 스위치에서 복호화하고, 내부 서버로는 HTTP로 전달할 수 있다.

```text id="v0ybuh"
Client --HTTPS--> L7 Switch --HTTP--> Web Server
```

이렇게 하면 인증서 관리와 암복호화 부담을 L7 스위치에서 처리할 수 있다.

---

## 헬스 체크

L7 스위치는 서버가 정상적으로 동작하는지 주기적으로 확인한다.

예시:

```http id="sljmcj"
GET /health
```

정상 서버에는 트래픽을 보내고, 장애가 발생한 서버에는 트래픽을 보내지 않는다.

---

## 4. L7 스위치의 장점

| 장점         | 설명                        |
| ---------- | ------------------------- |
| 정교한 트래픽 분산 | URL, 헤더, 쿠키 등을 기준으로 분산 가능 |
| 장애 대응      | 비정상 서버를 자동 제외             |
| 서비스별 라우팅   | 마이크로서비스 구조에 적합            |
| 보안 정책 적용   | 특정 요청 차단, 인증 연동 가능        |
| SSL 처리     | 인증서와 암복호화 처리 가능           |

---

## 5. L7 스위치의 단점

| 단점        | 설명                               |
| --------- | -------------------------------- |
| 처리 비용 증가  | 애플리케이션 데이터를 분석해야 하므로 부하가 큼       |
| 설정 복잡도 증가 | 라우팅 규칙, 인증서, 헬스 체크 설정 필요         |
| 병목 가능성    | 모든 요청이 L7 장비를 거치므로 병목 지점이 될 수 있음 |

---

## 6. L4 스위치와 L7 스위치 비교

L7 스위치를 이해하려면 L4 스위치와 비교하는 것이 좋다.

| 구분    | L4 스위치        | L7 스위치                           |
| ----- | ------------- | -------------------------------- |
| 처리 계층 | 전송 계층         | 애플리케이션 계층                        |
| 판단 기준 | IP 주소, 포트 번호  | URL, HTTP 헤더, 쿠키, 요청 경로          |
| 속도    | 상대적으로 빠름      | 상대적으로 느림                         |
| 기능    | 단순 부하 분산      | 정교한 요청 기반 라우팅                    |
| 예시    | TCP 443 요청 분산 | `/api/users` 요청을 User Server로 전달 |

예를 들어 같은 443 포트 요청이라도 L4 스위치는 모두 동일한 HTTPS 트래픽으로 본다.
반면 L7 스위치는 HTTPS 내부의 HTTP 요청 내용을 해석해 경로별로 다른 서버에 전달할 수 있다.

---

## 7. 면접 포인트

L7 스위치는 애플리케이션 계층의 정보를 기반으로 트래픽을 분산하는 장비이다.
IP와 포트뿐 아니라 URL, HTTP 헤더, 쿠키, 요청 경로 등을 확인할 수 있어 마이크로서비스 환경에서 정교한 라우팅에 사용된다.

---

# 2.3.3 인터넷 계층을 처리하는 기기

인터넷 계층을 처리하는 대표적인 기기는 다음과 같다.

* 라우터
* L3 스위치

이 장비들은 주로 **IP 주소**를 기준으로 패킷을 전달한다.

---

# 라우터

## 1. 라우터란?

**라우터**는 서로 다른 네트워크를 연결하고, 패킷이 목적지까지 가는 경로를 결정하는 장비이다.

예를 들어 집에서 인터넷을 사용할 때 공유기는 내부 네트워크와 외부 인터넷을 연결하는 라우터 역할을 한다.

```text id="mj9dc9"
내 PC → 공유기/라우터 → 인터넷 → 목적지 서버
```

---

## 2. 라우터의 주요 역할

## 네트워크 간 연결

라우터는 서로 다른 네트워크를 연결한다.

```text id="zrq2c6"
192.168.0.0/24 네트워크
        ↓
      Router
        ↓
10.0.0.0/24 네트워크
```

---

## 라우팅

라우터는 목적지 IP 주소를 보고 다음 홉을 결정한다.

```text id="spxv1r"
목적지 IP 확인
↓
라우팅 테이블 조회
↓
다음 홉 결정
↓
패킷 전달
```

라우팅 테이블에는 목적지 네트워크와 다음으로 보낼 경로 정보가 저장되어 있다.

---

## NAT

가정이나 회사에서는 사설 IP를 사용하는 경우가 많다.
라우터는 NAT를 통해 사설 IP와 공인 IP를 변환할 수 있다.

```text id="vfiph3"
내 PC: 192.168.0.10
공유기 공인 IP: 203.0.113.10
```

외부 인터넷에서는 내 PC의 사설 IP가 직접 보이지 않고, 공유기의 공인 IP로 통신하는 것처럼 보인다.

---

## 패킷 필터링

라우터는 특정 IP나 포트에 대한 접근을 제한할 수 있다.
기본적인 방화벽 역할을 수행하기도 한다.

---

## 3. 라우터가 보는 정보

라우터는 주로 IP 헤더를 확인한다.

주요 정보:

* 출발지 IP 주소
* 목적지 IP 주소
* TTL
* 프로토콜 정보
* 라우팅 테이블

라우터는 HTTP URL이나 쿠키 같은 애플리케이션 데이터는 기본적으로 보지 않는다.

---

## 4. 라우터 동작 예시

사용자가 `8.8.8.8`로 패킷을 보낸다고 하자.

```text id="wnwwmd"
목적지 IP: 8.8.8.8
↓
라우터가 라우팅 테이블 조회
↓
다음 홉으로 패킷 전달
```

라우터는 목적지까지 직접 연결되어 있지 않아도, 다음에 어느 라우터로 보내야 하는지만 알면 된다.

---

# L3 스위치

## 1. L3 스위치란?

**L3 스위치**는 스위치의 빠른 처리 성능과 라우터의 IP 기반 라우팅 기능을 함께 제공하는 장비이다.

즉, L2 스위치처럼 LAN 내부 트래픽을 빠르게 처리하면서, 서로 다른 네트워크 간 라우팅도 수행할 수 있다.

---

## 2. L3 스위치의 주요 역할

* VLAN 간 라우팅
* IP 기반 패킷 전달
* 내부망 라우팅
* 대규모 기업 네트워크에서 빠른 트래픽 처리

예를 들어 회사 내부에서 부서별 VLAN이 나뉘어 있다고 하자.

```text id="wvfsys"
개발팀 VLAN: 192.168.10.0/24
인사팀 VLAN: 192.168.20.0/24
영업팀 VLAN: 192.168.30.0/24
```

서로 다른 VLAN 간 통신이 필요할 때 L3 스위치가 라우팅을 수행할 수 있다.

---

## 3. 라우터와 L3 스위치 비교

| 구분    | 라우터                    | L3 스위치               |
| ----- | ---------------------- | -------------------- |
| 주요 목적 | 서로 다른 네트워크 연결          | LAN 내부 고속 라우팅        |
| 사용 위치 | 외부망 연결, WAN 연결         | 기업 내부망, 데이터센터        |
| 처리 기준 | IP 주소                  | IP 주소                |
| 특징    | 다양한 WAN 기능, NAT, 보안 기능 | 빠른 패킷 처리, VLAN 간 라우팅 |
| 예시    | 집 공유기, ISP 라우터         | 회사 코어 스위치            |

---

## 4. 면접 포인트

라우터와 L3 스위치는 모두 IP 주소를 기준으로 패킷을 전달한다.
라우터는 주로 서로 다른 네트워크나 외부 인터넷을 연결하는 데 사용되고, L3 스위치는 기업 내부망에서 VLAN 간 라우팅과 고속 패킷 처리를 위해 사용된다.

---

# 2.3.4 데이터 링크 계층을 처리하는 기기

데이터 링크 계층을 처리하는 대표적인 기기는 다음과 같다.

* L2 스위치
* 브리지

이 장비들은 주로 **MAC 주소**를 기준으로 프레임을 전달한다.

---

# L2 스위치

## 1. L2 스위치란?

**L2 스위치**는 데이터 링크 계층에서 동작하며, MAC 주소를 기반으로 프레임을 전달하는 장비이다.

회사나 가정에서 여러 PC를 유선 LAN으로 연결할 때 많이 사용된다.

```text id="zfvv7m"
PC1 ─┐
PC2 ─┼─ L2 Switch
PC3 ─┘
```

---

## 2. L2 스위치의 주요 역할

## MAC 주소 학습

L2 스위치는 각 포트에 어떤 MAC 주소의 장비가 연결되어 있는지 학습한다.

```text id="uptemu"
Port 1 → AA:AA:AA:AA:AA:AA
Port 2 → BB:BB:BB:BB:BB:BB
Port 3 → CC:CC:CC:CC:CC:CC
```

이 정보를 **MAC 주소 테이블**이라고 한다.

---

## 프레임 전달

스위치는 목적지 MAC 주소를 보고 해당 장비가 연결된 포트로만 프레임을 전달한다.

```text id="w5bw6l"
목적지 MAC 확인
↓
MAC 주소 테이블 조회
↓
해당 포트로 프레임 전달
```

---

## 플러딩

스위치가 목적지 MAC 주소를 모르는 경우에는 들어온 포트를 제외한 모든 포트로 프레임을 보낸다.
이를 **플러딩**이라고 한다.

```text id="q3o2ef"
목적지 MAC을 모름
↓
모든 포트로 전송
↓
응답을 통해 MAC 주소 학습
```

---

## 브로드캐스트 전달

브로드캐스트 프레임은 같은 네트워크 안의 모든 장비에게 전달된다.

예를 들어 ARP 요청은 브로드캐스트 방식으로 전달된다.

```text id="b98t92"
"이 IP 주소를 가진 장비의 MAC 주소가 뭐야?"
```

---

## 3. L2 스위치가 보는 정보

L2 스위치는 Ethernet 프레임의 MAC 주소를 본다.

주요 정보:

* 출발지 MAC 주소
* 목적지 MAC 주소
* VLAN 태그
* 프레임 타입

L2 스위치는 기본적으로 IP 주소나 포트 번호를 기준으로 라우팅하지 않는다.

---

## 4. L2 스위치와 허브의 차이

| 구분    | 허브        | L2 스위치     |
| ----- | --------- | ---------- |
| 처리 계층 | 물리 계층     | 데이터 링크 계층  |
| 판단 기준 | 없음        | MAC 주소     |
| 전송 방식 | 모든 포트로 전송 | 목적지 포트로 전송 |
| 충돌 영역 | 전체가 하나    | 포트별로 분리    |
| 효율성   | 낮음        | 높음         |

허브는 들어온 신호를 모든 포트로 뿌린다.
반면 L2 스위치는 MAC 주소를 학습하고 목적지 포트로만 프레임을 전달한다.

---

## 5. 브리지

브리지는 데이터 링크 계층에서 네트워크 세그먼트를 연결하는 장비이다.

L2 스위치와 비슷하게 MAC 주소를 기반으로 프레임을 전달한다.

```text id="jyg1gm"
Network A ─ Bridge ─ Network B
```

과거에는 네트워크 구간을 나누고 충돌 영역을 줄이기 위해 브리지를 많이 사용했다.
현대 네트워크에서는 대부분 L2 스위치가 브리지 역할을 대체한다.

---

## 6. L2 스위치와 브리지 비교

| 구분    | 브리지          | L2 스위치        |
| ----- | ------------ | ------------- |
| 처리 계층 | 데이터 링크 계층    | 데이터 링크 계층     |
| 판단 기준 | MAC 주소       | MAC 주소        |
| 포트 수  | 적음           | 많음            |
| 처리 방식 | 소프트웨어 기반이 많음 | 하드웨어 기반 고속 처리 |
| 현재 사용 | 제한적          | 일반적으로 사용      |

---

## 7. 면접 포인트

L2 스위치는 MAC 주소를 기반으로 프레임을 전달하는 장비이다.
MAC 주소 테이블을 학습하여 목적지 장비가 연결된 포트로만 프레임을 보내기 때문에 허브보다 효율적이다.

---

# 2.3.5 물리 계층을 처리하는 기기

물리 계층은 데이터를 실제 신호로 전송하는 계층이다.

물리 계층을 처리하는 대표적인 기기는 다음과 같다.

* NIC
* 리피터
* 허브
* AP

---

# NIC

## 1. NIC란?

**NIC**는 Network Interface Card의 약자이다.
컴퓨터나 서버가 네트워크에 연결되기 위해 사용하는 네트워크 인터페이스 장치이다.

일반적으로 랜카드라고도 부른다.

```text id="qx50xs"
컴퓨터 ─ NIC ─ 네트워크 케이블 또는 무선 네트워크
```

---

## 2. NIC의 주요 역할

NIC는 컴퓨터 내부의 데이터를 네트워크로 보낼 수 있는 신호로 변환한다.

주요 역할:

* 데이터를 전기 신호, 광 신호, 무선 신호로 변환
* 수신한 신호를 컴퓨터가 이해할 수 있는 데이터로 변환
* MAC 주소 보유
* 네트워크 연결 인터페이스 제공

NIC는 물리 계층과 데이터 링크 계층에 걸친 장비로 볼 수 있다.
신호 변환은 물리 계층 역할이고, MAC 주소 처리는 데이터 링크 계층 역할이다.

---

# 리피터

## 1. 리피터란?

**리피터**는 약해진 신호를 증폭하거나 재생하여 더 멀리 전달하는 장비이다.

네트워크 신호는 케이블을 따라 이동하면서 약해질 수 있다.
리피터는 이 신호를 다시 강하게 만들어 전송 거리를 늘린다.

```text id="k0z01u"
PC ──── 약해진 신호 ──── Repeater ──── 강해진 신호 ──── Server
```

---

## 2. 리피터의 특징

* 물리 계층에서 동작한다.
* MAC 주소나 IP 주소를 보지 않는다.
* 데이터 내용을 해석하지 않는다.
* 신호를 증폭하거나 재생한다.

리피터는 단순히 신호를 다시 살려주는 장비라고 이해하면 된다.

---

# 허브

## 1. 허브란?

**허브**는 여러 네트워크 장비를 연결하는 물리 계층 장비이다.

허브는 한 포트로 들어온 신호를 나머지 모든 포트로 그대로 전달한다.

```text id="zmkp44"
PC1 ─┐
PC2 ─┼─ Hub
PC3 ─┘
```

PC1이 PC2에게 데이터를 보내더라도 허브는 목적지를 판단하지 못한다.
그래서 PC2뿐 아니라 PC3에게도 신호를 전달한다.

---

## 2. 허브의 특징

| 특징     | 설명           |
| ------ | ------------ |
| 처리 계층  | 물리 계층        |
| 판단 기준  | 없음           |
| 전송 방식  | 모든 포트로 신호 전달 |
| 충돌 가능성 | 높음           |
| 효율성    | 낮음           |

현재는 대부분 L2 스위치가 허브를 대체한다.

---

# AP

## 1. AP란?

**AP**는 Access Point의 약자이다.
무선 장치가 유선 네트워크에 접속할 수 있도록 연결해주는 장비이다.

쉽게 말해 Wi-Fi 접속 지점을 제공하는 장비이다.

```text id="q5hwvw"
스마트폰 )) 
노트북   ))  AP ─ 유선 네트워크 ─ 인터넷
태블릿   ))
```

---

## 2. AP의 주요 역할

* 무선 네트워크 제공
* 무선 신호와 유선 네트워크 연결
* Wi-Fi 장치의 접속 관리
* 무선 프레임 송수신
* 인증 및 암호화 기능 제공 가능

AP는 물리 계층뿐 아니라 데이터 링크 계층 기능도 일부 수행한다.
무선 신호를 처리하면서 MAC 주소 기반 통신도 다루기 때문이다.

---

# 계층별 네트워크 기기 전체 정리

| 계층        | 대표 기기            | 판단 기준            | 주요 역할             |
| --------- | ---------------- | ---------------- | ----------------- |
| 애플리케이션 계층 | L7 스위치           | URL, HTTP 헤더, 쿠키 | 요청 내용 기반 로드밸런싱    |
| 전송 계층     | L4 스위치           | IP 주소, 포트 번호     | 포트 기반 로드밸런싱       |
| 인터넷 계층    | 라우터, L3 스위치      | IP 주소            | 네트워크 간 패킷 전달      |
| 데이터 링크 계층 | L2 스위치, 브리지      | MAC 주소           | 같은 네트워크 내 프레임 전달  |
| 물리 계층     | NIC, 리피터, 허브, AP | 신호               | 실제 신호 송수신, 증폭, 연결 |

# 계층별 장비 흐름 예시

사용자가 웹 서버에 접속하는 흐름을 장비 중심으로 보면 다음과 같다.

```text id="c2hb70"
사용자 PC
  ↓
NIC
  ↓
L2 스위치
  ↓
라우터
  ↓
L4 또는 L7 로드밸런서
  ↓
웹 서버
```

각 장비는 서로 다른 기준으로 데이터를 처리한다.

```text id="j5gy3q"
NIC: 데이터를 신호로 변환
L2 스위치: MAC 주소 기준 전달
라우터: IP 주소 기준 전달
L4 스위치: IP + 포트 기준 분산
L7 스위치: HTTP 요청 내용 기준 분산
```

# 면접 포인트

## Q1. 네트워크 기기의 처리 범위란 무엇인가요?

네트워크 기기의 처리 범위는 해당 장비가 어느 계층의 정보를 해석하고 처리할 수 있는지를 의미합니다.
상위 계층 장비는 하위 계층 정보를 함께 처리할 수 있지만, 하위 계층 장비는 상위 계층 정보를 해석하지 못합니다.

## Q2. L7 스위치는 무엇인가요?

L7 스위치는 애플리케이션 계층의 정보를 기반으로 트래픽을 분산하는 장비입니다.
URL, HTTP 헤더, 쿠키, 요청 경로 등을 확인하여 요청을 적절한 서버로 전달할 수 있습니다.

## Q3. 라우터는 어떤 역할을 하나요?

라우터는 서로 다른 네트워크를 연결하고, 목적지 IP 주소를 기준으로 패킷의 다음 경로를 결정하는 장비입니다.
라우팅 테이블을 참고하여 패킷을 다음 홉으로 전달합니다.

## Q4. L2 스위치는 어떤 기준으로 데이터를 전달하나요?

L2 스위치는 MAC 주소를 기준으로 프레임을 전달합니다.
MAC 주소 테이블을 학습하여 목적지 장비가 연결된 포트로만 프레임을 전송합니다.

## Q5. 허브와 스위치의 차이는 무엇인가요?

허브는 들어온 신호를 모든 포트로 전달하는 물리 계층 장비입니다.
반면 L2 스위치는 MAC 주소를 보고 목적지 포트로만 프레임을 전달하는 데이터 링크 계층 장비입니다.
따라서 스위치가 허브보다 효율적입니다.

## Q6. 라우터와 L3 스위치의 차이는 무엇인가요?

둘 다 IP 주소를 기준으로 패킷을 전달합니다.
라우터는 주로 서로 다른 네트워크나 외부 인터넷을 연결하는 데 사용되고, L3 스위치는 기업 내부망에서 VLAN 간 라우팅과 고속 패킷 처리를 위해 사용됩니다.

## Q7. AP는 어떤 장비인가요?

AP는 Access Point의 약자로, 무선 장치가 유선 네트워크에 접속할 수 있도록 연결해주는 장비입니다.
Wi-Fi 접속 지점을 제공하며, 무선 신호와 유선 네트워크 사이를 연결합니다.

```text id="etzfge"
애플리케이션 계층: L7 스위치
전송 계층: L4 스위치
인터넷 계층: 라우터, L3 스위치
데이터 링크 계층: L2 스위치, 브리지
물리 계층: NIC, 리피터, 허브, AP
```

## 계층별 판단 기준

```text id="s7kupp"
L7 스위치: URL, HTTP 헤더, 쿠키
L4 스위치: IP 주소 + 포트 번호
라우터/L3 스위치: IP 주소
L2 스위치/브리지: MAC 주소
리피터/허브: 신호
```

## 장비별 한 줄 정리

* L7 스위치: HTTP 요청 내용을 보고 트래픽을 분산한다.
* L4 스위치: IP와 포트 번호를 보고 트래픽을 분산한다.
* 라우터: IP 주소를 보고 다른 네트워크로 패킷을 전달한다.
* L3 스위치: IP 주소 기반으로 내부망에서 고속 라우팅을 수행한다.
* L2 스위치: MAC 주소를 보고 같은 네트워크 안에서 프레임을 전달한다.
* 브리지: MAC 주소 기반으로 네트워크 세그먼트를 연결한다.
* NIC: 컴퓨터가 네트워크에 접속할 수 있게 해주는 인터페이스이다.
* 리피터: 약해진 신호를 증폭하거나 재생한다.
* 허브: 들어온 신호를 모든 포트로 전달한다.
* AP: 무선 장치를 유선 네트워크에 연결해주는 접속 지점이다.

# 암기용 한 줄 정리

* 상위 계층 장비는 하위 계층 정보를 함께 처리할 수 있다.
* L7 스위치는 URL, 헤더, 쿠키 등 애플리케이션 정보를 본다.
* L4 스위치는 IP와 포트 번호를 본다.
* 라우터와 L3 스위치는 IP 주소를 본다.
* L2 스위치와 브리지는 MAC 주소를 본다.
* 리피터와 허브는 주소를 보지 않고 신호만 처리한다.
* 허브는 모든 포트로 보내고, 스위치는 목적지 포트로 보낸다.
* 라우터는 네트워크 간 연결, L3 스위치는 내부망 고속 라우팅에 주로 사용된다.
