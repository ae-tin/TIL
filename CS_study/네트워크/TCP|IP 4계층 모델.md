# 2.2 TCP/IP 4계층 모델

## 학습 목표

이 단원에서는 인터넷 통신의 핵심 구조인 **TCP/IP 4계층 모델**을 학습한다.
네트워크 통신이 한 번에 이루어지는 것이 아니라, 여러 계층이 역할을 나누어 데이터를 처리한다는 점을 이해하는 것이 중요하다.

학습 후 다음 내용을 설명할 수 있어야 한다.

* TCP/IP 4계층 모델의 구조
* 각 계층의 역할
* 각 계층에서 사용되는 대표 프로토콜
* PDU의 의미
* 데이터가 계층을 거치며 캡슐화되는 과정
* 계층별 PDU 이름

---

# 2.2.1 계층 구조

## 1. TCP/IP 4계층 모델이란?

**TCP/IP 4계층 모델**은 인터넷에서 데이터를 주고받기 위해 네트워크 기능을 4개의 계층으로 나눈 모델이다.

각 계층은 자신만의 역할을 담당하며, 위아래 계층과 협력해서 데이터를 전송한다.

```text id="kbhznn"
[ 애플리케이션 계층 ]
[ 전송 계층 ]
[ 인터넷 계층 ]
[ 네트워크 접근 계층 ]
```

TCP/IP 모델은 실제 인터넷에서 가장 널리 사용되는 네트워크 모델이다.

---

## 2. 계층 구조를 사용하는 이유

네트워크 통신은 매우 복잡하다.

예를 들어 웹 브라우저에서 `https://example.com`에 접속한다고 해보자.

이 과정에는 다음 작업들이 필요하다.

* 사용자가 요청한 HTTP 메시지 생성
* 데이터를 신뢰성 있게 전송
* 목적지 IP 주소로 패킷 전달
* 실제 물리적 네트워크를 통해 비트 전송

이 모든 기능을 하나의 덩어리로 만들면 구조가 복잡해지고 유지보수가 어렵다.
그래서 네트워크 기능을 계층별로 나누어 관리한다.

## 3. 계층 구조의 장점

| 장점       | 설명                         |
| -------- | -------------------------- |
| 역할 분리    | 각 계층이 특정 기능만 담당한다.         |
| 유지보수 용이  | 특정 계층만 수정하거나 교체하기 쉽다.      |
| 표준화 용이   | 계층별 프로토콜을 표준화할 수 있다.       |
| 문제 분석 용이 | 장애가 어느 계층에서 발생했는지 파악하기 쉽다. |
| 확장성      | 새로운 기술을 특정 계층에 추가하기 쉽다.    |

---

# 1계층: 네트워크 접근 계층

## 1. 역할

**네트워크 접근 계층**은 실제 네트워크 장비를 통해 데이터를 물리적으로 전송하는 계층이다.

이 계층은 같은 네트워크 안에서 데이터를 어떻게 전달할지 담당한다.

주요 역할은 다음과 같다.

* 물리적 데이터 전송
* MAC 주소 기반 통신
* 프레임 단위 전송
* LAN, Wi-Fi 같은 물리적 네트워크 처리
* 네트워크 인터페이스 카드, 케이블, 스위치 등과 관련

## 2. 대표 프로토콜과 기술

| 프로토콜/기술  | 설명                  |
| -------- | ------------------- |
| Ethernet | 유선 LAN에서 사용하는 대표 기술 |
| Wi-Fi    | 무선 LAN 기술           |
| ARP      | IP 주소를 MAC 주소로 변환   |
| MAC      | 네트워크 장비의 물리적 주소     |
| PPP      | 점대점 연결 프로토콜         |

## 3. 주소 체계

네트워크 접근 계층에서는 **MAC 주소**를 사용한다.

MAC 주소는 네트워크 장비에 부여된 물리적 주소이다.

예시:

```text id="vh9nss"
00:1A:2B:3C:4D:5E
```

## 4. 핵심 개념

네트워크 접근 계층은 “실제로 데이터를 네트워크 선이나 무선 신호를 통해 보내는 계층”이라고 이해하면 된다.

---

# 2계층: 인터넷 계층

## 1. 역할

**인터넷 계층**은 데이터를 목적지까지 전달하기 위한 경로를 결정하는 계층이다.

주요 역할은 다음과 같다.

* IP 주소 기반 통신
* 패킷 전달
* 라우팅
* 서로 다른 네트워크 간 데이터 이동
* 목적지까지 갈 경로 선택

## 2. 대표 프로토콜

| 프로토콜 | 설명                    |
| ---- | --------------------- |
| IP   | 목적지 IP 주소를 기반으로 패킷 전달 |
| ICMP | 네트워크 오류 및 상태 확인       |
| ARP  | IP 주소를 MAC 주소로 변환     |
| RARP | MAC 주소를 IP 주소로 변환     |

## 3. 주소 체계

인터넷 계층에서는 **IP 주소**를 사용한다.

예시:

```text id="mdwrgc"
192.168.0.10
8.8.8.8
```

IP 주소는 네트워크에서 장치를 논리적으로 식별하기 위한 주소이다.

## 4. 라우팅

라우팅은 패킷이 목적지까지 가기 위해 어떤 경로를 거칠지 결정하는 과정이다.

```text id="kitijv"
내 PC → 공유기 → ISP 라우터 → 백본망 → 목적지 서버
```

라우터는 패킷의 목적지 IP 주소를 보고 다음에 어디로 보낼지 결정한다.

## 5. 핵심 개념

인터넷 계층은 “목적지 IP 주소를 보고 데이터를 어디로 보낼지 결정하는 계층”이다.

---

# 3계층: 전송 계층

## 1. 역할

**전송 계층**은 송신자와 수신자 사이의 데이터 전송을 담당하는 계층이다.

인터넷 계층이 “어느 컴퓨터로 보낼지”를 담당한다면, 전송 계층은 “그 컴퓨터의 어떤 프로그램으로 보낼지”를 담당한다.

주요 역할은 다음과 같다.

* 프로세스 간 통신
* 포트 번호 기반 통신
* 데이터 분할 및 재조립
* 신뢰성 있는 전송
* 흐름 제어
* 혼잡 제어
* 오류 제어

## 2. 대표 프로토콜

| 프로토콜 | 설명               |
| ---- | ---------------- |
| TCP  | 신뢰성 있는 연결 지향형 전송 |
| UDP  | 빠른 비연결형 전송       |

---

## 3. TCP

**TCP**는 Transmission Control Protocol의 약자이다.
신뢰성 있는 데이터 전송을 제공한다.

TCP의 특징은 다음과 같다.

* 연결 지향 방식
* 데이터 순서 보장
* 데이터 손실 시 재전송
* 흐름 제어
* 혼잡 제어
* 3-way handshake 사용

TCP는 데이터가 정확하게 도착해야 하는 서비스에 사용된다.

예시:

* 웹
* 이메일
* 파일 전송
* SSH
* 데이터베이스 연결

---

## 4. UDP

**UDP**는 User Datagram Protocol의 약자이다.
연결 과정 없이 데이터를 빠르게 전송하는 프로토콜이다.

UDP의 특징은 다음과 같다.

* 비연결형 방식
* 데이터 순서 보장 없음
* 재전송 없음
* TCP보다 구조가 단순함
* 속도가 빠름

UDP는 실시간성이 중요한 서비스에 사용된다.

예시:

* 온라인 게임
* 실시간 스트리밍
* 음성 통화
* 화상 회의
* DNS

---

## 5. 포트 번호

전송 계층에서는 **포트 번호**를 사용한다.

IP 주소가 컴퓨터를 찾는 주소라면, 포트 번호는 해당 컴퓨터 안의 특정 프로그램을 찾는 번호이다.

```text id="rodcgp"
IP 주소: 어느 컴퓨터인가?
포트 번호: 그 컴퓨터의 어떤 프로그램인가?
```

예시:

| 포트     | 프로토콜/서비스   |
| ------ | ---------- |
| 20, 21 | FTP        |
| 22     | SSH        |
| 25     | SMTP       |
| 53     | DNS        |
| 80     | HTTP       |
| 443    | HTTPS      |
| 3306   | MySQL      |
| 5432   | PostgreSQL |
| 6379   | Redis      |

## 6. 핵심 개념

전송 계층은 “목적지 컴퓨터 안에서 어떤 애플리케이션으로 데이터를 보낼지 결정하고, 데이터 전송의 신뢰성을 관리하는 계층”이다.

---

# 4계층: 애플리케이션 계층

## 1. 역할

**애플리케이션 계층**은 사용자가 직접 사용하는 서비스와 가장 가까운 계층이다.

웹 브라우저, 이메일 클라이언트, 파일 전송 프로그램 등이 이 계층의 프로토콜을 사용한다.

주요 역할은 다음과 같다.

* 사용자 서비스 제공
* 애플리케이션 간 데이터 교환
* 파일 전송
* 이메일 송수신
* 웹 요청과 응답
* 도메인 이름 해석

## 2. 대표 프로토콜

| 프로토콜   | 설명             |
| ------ | -------------- |
| HTTP   | 웹 요청과 응답       |
| HTTPS  | 암호화된 웹 통신      |
| DNS    | 도메인을 IP 주소로 변환 |
| FTP    | 파일 전송          |
| SMTP   | 이메일 송신         |
| POP3   | 이메일 수신         |
| IMAP   | 이메일 동기화 및 수신   |
| SSH    | 원격 서버 접속       |
| Telnet | 원격 접속          |
| DHCP   | IP 주소 자동 할당    |

## 3. HTTP 예시

브라우저에서 웹 페이지에 접속하면 애플리케이션 계층에서는 HTTP 요청이 만들어진다.

```http id="vrnssh"
GET /index.html HTTP/1.1
Host: example.com
```

서버는 요청을 처리하고 HTTP 응답을 보낸다.

```http id="51g3gj"
HTTP/1.1 200 OK
Content-Type: text/html
```

## 4. 핵심 개념

애플리케이션 계층은 “사용자가 사용하는 서비스의 통신 규칙을 담당하는 계층”이다.

---

# TCP/IP 4계층 전체 정리

| 계층         | 주요 역할        | 주소/식별자 | 대표 프로토콜                   | PDU        |
| ---------- | ------------ | ------ | ------------------------- | ---------- |
| 애플리케이션 계층  | 사용자 서비스 제공   | 데이터    | HTTP, DNS, FTP, SMTP, SSH | 메시지        |
| 전송 계층      | 프로세스 간 통신    | 포트 번호  | TCP, UDP                  | 세그먼트/데이터그램 |
| 인터넷 계층     | 네트워크 간 패킷 전달 | IP 주소  | IP, ICMP, ARP             | 패킷         |
| 네트워크 접근 계층 | 물리적 네트워크 전송  | MAC 주소 | Ethernet, Wi-Fi           | 프레임        |

# 데이터 전송 흐름

웹 브라우저에서 서버로 데이터를 보낼 때의 흐름은 다음과 같다.

```text id="98fh1n"
[애플리케이션 계층]
HTTP 요청 생성

↓
[전송 계층]
TCP 헤더 추가
출발지 포트, 목적지 포트 포함

↓
[인터넷 계층]
IP 헤더 추가
출발지 IP, 목적지 IP 포함

↓
[네트워크 접근 계층]
Ethernet 헤더 추가
출발지 MAC, 목적지 MAC 포함

↓
물리적 네트워크로 전송
```

수신 측에서는 반대로 각 계층의 헤더를 제거하면서 데이터를 해석한다.

```text id="tzi91u"
송신 측: 위에서 아래로 내려가며 헤더 추가
수신 측: 아래에서 위로 올라가며 헤더 제거
```

# 캡슐화와 역캡슐화

## 1. 캡슐화

**캡슐화**는 데이터를 전송하기 위해 각 계층에서 헤더를 붙이는 과정이다.

송신 측에서는 데이터가 상위 계층에서 하위 계층으로 내려가면서 각 계층의 헤더가 추가된다.

```text id="6s8664"
데이터
↓
TCP 헤더 + 데이터
↓
IP 헤더 + TCP 헤더 + 데이터
↓
Ethernet 헤더 + IP 헤더 + TCP 헤더 + 데이터
```

## 2. 역캡슐화

**역캡슐화**는 수신 측에서 각 계층의 헤더를 제거하면서 원래 데이터를 복원하는 과정이다.

```text id="lind7c"
Ethernet 헤더 + IP 헤더 + TCP 헤더 + 데이터
↓
IP 헤더 + TCP 헤더 + 데이터
↓
TCP 헤더 + 데이터
↓
데이터
```

## 3. 핵심 개념

캡슐화는 데이터를 보내기 위해 계층별 정보를 붙이는 과정이고, 역캡슐화는 받은 데이터에서 계층별 정보를 제거하며 원래 데이터를 복원하는 과정이다.

---

# 2.2.2 PDU

## 1. PDU란?

**PDU**는 Protocol Data Unit의 약자이다.
각 계층에서 처리하는 데이터 단위를 의미한다.

네트워크 데이터는 계층을 거치면서 이름이 달라진다.
같은 데이터라도 어느 계층에서 바라보느냐에 따라 PDU 이름이 달라진다.

---

## 2. 계층별 PDU

| TCP/IP 계층  | PDU 이름        | 설명                    |
| ---------- | ------------- | --------------------- |
| 애플리케이션 계층  | 메시지           | 사용자가 주고받는 실제 데이터      |
| 전송 계층      | 세그먼트 또는 데이터그램 | TCP/UDP 헤더가 붙은 데이터    |
| 인터넷 계층     | 패킷            | IP 헤더가 붙은 데이터         |
| 네트워크 접근 계층 | 프레임           | MAC 헤더가 붙은 데이터        |
| 물리적 전송     | 비트            | 실제 전기 신호, 광 신호, 무선 신호 |

---

## 3. TCP와 UDP의 PDU 차이

전송 계층에서는 사용하는 프로토콜에 따라 PDU 이름이 달라진다.

| 프로토콜 | PDU 이름 |
| ---- | ------ |
| TCP  | 세그먼트   |
| UDP  | 데이터그램  |

TCP는 데이터를 신뢰성 있게 전송하기 위해 순서 번호, 확인 응답, 재전송 등의 기능을 사용한다.
UDP는 연결 없이 빠르게 보내는 방식이기 때문에 데이터그램이라는 표현을 사용한다.

---

## 4. PDU 변화 과정

애플리케이션 계층에서 생성된 데이터가 하위 계층으로 내려가면서 PDU 이름이 바뀐다.

```text id="n0zvo5"
애플리케이션 계층: 메시지
↓
전송 계층: 세그먼트 또는 데이터그램
↓
인터넷 계층: 패킷
↓
네트워크 접근 계층: 프레임
↓
물리적 전송: 비트
```

예를 들어 웹 브라우저가 HTTP 요청을 보낸다면 다음과 같이 볼 수 있다.

```text id="l2i3wa"
HTTP 메시지
↓
TCP 세그먼트
↓
IP 패킷
↓
Ethernet 프레임
↓
비트
```

---

## 5. 헤더와 페이로드

PDU는 보통 **헤더**와 **페이로드**로 구성된다.

```text id="bw95b4"
[ Header ][ Payload ]
```

## 헤더

헤더는 데이터를 전달하기 위해 필요한 제어 정보이다.

예시:

* 출발지 주소
* 목적지 주소
* 포트 번호
* 순서 번호
* 오류 검출 정보
* 프로토콜 정보

## 페이로드

페이로드는 실제로 전달하려는 데이터이다.

예를 들어 HTTP 요청을 보낼 때, HTTP 메시지는 전송 계층 입장에서 페이로드가 된다.

```text id="0no3dd"
전송 계층 PDU = TCP 헤더 + HTTP 메시지
인터넷 계층 PDU = IP 헤더 + TCP 세그먼트
네트워크 접근 계층 PDU = Ethernet 헤더 + IP 패킷
```

즉, 상위 계층의 PDU는 하위 계층에서 페이로드가 된다.

---

# 계층별 헤더 정보

## 1. 전송 계층 헤더

TCP 또는 UDP 헤더에는 포트 번호 정보가 들어간다.

```text id="s11ezm"
[ TCP Header ][ Application Data ]
```

주요 정보:

* 출발지 포트
* 목적지 포트
* 순서 번호
* 확인 응답 번호
* 체크섬

UDP 헤더는 TCP보다 단순하다.

주요 정보:

* 출발지 포트
* 목적지 포트
* 길이
* 체크섬

---

## 2. 인터넷 계층 헤더

IP 헤더에는 IP 주소 정보가 들어간다.

```text id="3b4h3r"
[ IP Header ][ TCP Segment ]
```

주요 정보:

* 출발지 IP 주소
* 목적지 IP 주소
* TTL
* 프로토콜 정보
* 체크섬

TTL은 Time To Live의 약자로, 패킷이 네트워크에서 무한히 떠돌지 않도록 제한하는 값이다.

---

## 3. 네트워크 접근 계층 헤더

Ethernet 헤더에는 MAC 주소 정보가 들어간다.

```text id="bk55j3"
[ Ethernet Header ][ IP Packet ]
```

주요 정보:

* 출발지 MAC 주소
* 목적지 MAC 주소
* 타입 정보
* 오류 검출 정보

---

# 주소 체계 정리

TCP/IP 4계층에서는 계층마다 사용하는 식별자가 다르다.

| 계층         | 식별자             | 의미               |
| ---------- | --------------- | ---------------- |
| 애플리케이션 계층  | 도메인, URL, URI 등 | 사용자가 접근하는 서비스 식별 |
| 전송 계층      | 포트 번호           | 어떤 애플리케이션인지 식별   |
| 인터넷 계층     | IP 주소           | 어떤 호스트인지 식별      |
| 네트워크 접근 계층 | MAC 주소          | 같은 네트워크 내 장비 식별  |

예시로 `https://example.com`에 접속할 때를 생각해보자.

```text id="mpbg8e"
URL: https://example.com
IP 주소: example.com이 가리키는 서버 주소
포트 번호: 443
MAC 주소: 다음 홉 장비의 물리 주소
```

중요한 점은 MAC 주소가 최종 목적지까지 계속 유지되는 것이 아니라는 점이다.
MAC 주소는 같은 네트워크 구간에서 다음 장비까지 전달할 때 사용된다.

반면 IP 주소는 출발지에서 목적지까지의 논리적 주소로 사용된다.

# OSI 7계층과 TCP/IP 4계층 비교

TCP/IP 4계층은 OSI 7계층보다 실제 인터넷 구현에 더 가까운 모델이다.

| OSI 7계층      | TCP/IP 4계층 |
| ------------ | ---------- |
| 7. 응용 계층     | 애플리케이션 계층  |
| 6. 표현 계층     | 애플리케이션 계층  |
| 5. 세션 계층     | 애플리케이션 계층  |
| 4. 전송 계층     | 전송 계층      |
| 3. 네트워크 계층   | 인터넷 계층     |
| 2. 데이터 링크 계층 | 네트워크 접근 계층 |
| 1. 물리 계층     | 네트워크 접근 계층 |

OSI 7계층은 이론적 설명에 많이 사용되고, TCP/IP 4계층은 실제 인터넷 구조를 설명할 때 많이 사용된다.

# 예시: 웹 페이지 접속 과정

사용자가 브라우저에서 `https://example.com`에 접속한다고 가정하자.

## 1. 애플리케이션 계층

브라우저가 HTTP 요청 메시지를 만든다.

```http id="7rrh26"
GET / HTTP/1.1
Host: example.com
```

HTTPS를 사용한다면 TLS를 통해 암호화된 통신을 수행한다.

## 2. 전송 계층

HTTP 메시지는 TCP를 통해 전송된다.
목적지 포트는 HTTPS이므로 `443`번 포트이다.

```text id="6l4jan"
출발지 포트: 임시 포트
목적지 포트: 443
```

## 3. 인터넷 계층

목적지 서버의 IP 주소를 사용해 패킷을 전달한다.

```text id="s2s66g"
출발지 IP: 내 PC의 IP
목적지 IP: example.com 서버 IP
```

## 4. 네트워크 접근 계층

같은 네트워크 내에서 다음 장비로 데이터를 보내기 위해 MAC 주소를 사용한다.

```text id="adqzhn"
출발지 MAC: 내 PC의 MAC 주소
목적지 MAC: 공유기 또는 다음 홉의 MAC 주소
```

# 면접 포인트

## 1. TCP/IP 4계층을 설명해주세요.

TCP/IP 4계층은 인터넷 통신을 설명하기 위한 계층 모델입니다.
아래에서부터 네트워크 접근 계층, 인터넷 계층, 전송 계층, 애플리케이션 계층으로 구성됩니다.
각 계층은 물리적 전송, IP 기반 라우팅, 포트 기반 프로세스 통신, 사용자 서비스 제공 역할을 담당합니다.

## 2. 각 계층의 대표 프로토콜은 무엇인가요?

네트워크 접근 계층에는 Ethernet, Wi-Fi, ARP가 있고, 인터넷 계층에는 IP, ICMP가 있습니다.
전송 계층에는 TCP와 UDP가 있으며, 애플리케이션 계층에는 HTTP, HTTPS, DNS, FTP, SMTP, SSH 등이 있습니다.

## 3. PDU란 무엇인가요?

PDU는 Protocol Data Unit의 약자로, 각 계층에서 처리하는 데이터 단위를 의미합니다.
애플리케이션 계층에서는 메시지, 전송 계층에서는 세그먼트 또는 데이터그램, 인터넷 계층에서는 패킷, 네트워크 접근 계층에서는 프레임이라고 부릅니다.

## 4. 캡슐화란 무엇인가요?

캡슐화는 송신 측에서 데이터가 상위 계층에서 하위 계층으로 내려가면서 각 계층의 헤더가 추가되는 과정입니다.
예를 들어 HTTP 메시지에 TCP 헤더가 붙어 세그먼트가 되고, 여기에 IP 헤더가 붙어 패킷이 되며, 다시 Ethernet 헤더가 붙어 프레임이 됩니다.

## 5. IP 주소와 MAC 주소의 차이는 무엇인가요?

IP 주소는 목적지 호스트를 찾기 위한 논리적 주소이고, MAC 주소는 같은 네트워크 구간에서 장비를 식별하기 위한 물리적 주소입니다.
IP 주소는 출발지에서 목적지까지의 전체 통신에 사용되고, MAC 주소는 다음 홉까지 데이터를 전달할 때 사용됩니다.

# 암기용 한 줄 정리

* TCP/IP 4계층은 인터넷 통신을 4개의 역할로 나눈 모델이다.
* 애플리케이션 계층은 사용자 서비스와 가장 가깝다.
* 전송 계층은 포트 번호를 사용해 프로세스 간 통신을 담당한다.
* 인터넷 계층은 IP 주소를 사용해 목적지까지 패킷을 전달한다.
* 네트워크 접근 계층은 MAC 주소를 사용해 실제 네트워크로 데이터를 전송한다.
* PDU는 각 계층에서 처리하는 데이터 단위이다.
* TCP의 PDU는 세그먼트, UDP의 PDU는 데이터그램이다.
* 인터넷 계층의 PDU는 패킷이다.
* 네트워크 접근 계층의 PDU는 프레임이다.
* 캡슐화는 계층을 내려가며 헤더를 붙이는 과정이다.
* 역캡슐화는 계층을 올라가며 헤더를 제거하는 과정이다.
