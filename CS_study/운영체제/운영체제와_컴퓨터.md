# 3.1.1 운영체제의 역할과 구조

## 1. 운영체제란?

운영체제(OS, Operating System)는 **사용자·응용 프로그램과 하드웨어 사이를 연결하는 시스템 소프트웨어**다.

```text
사용자
  ↓
응용 프로그램
  ↓
운영체제
  ↓
CPU · 메모리 · 저장장치 · 입출력장치
```

응용 프로그램이 하드웨어를 직접 제어하면 프로그램 간 충돌, 자원 독점, 보안 문제가 발생할 수 있다.  
운영체제는 하드웨어 자원을 관리하고, 응용 프로그램이 안전하게 사용할 수 있도록 인터페이스를 제공한다.

---

## 2. 운영체제의 주요 역할

### 2.1 CPU 관리

여러 프로세스 중 어떤 프로세스에 CPU를 할당할지 결정한다.  
이를 **CPU 스케줄링**이라고 한다.

```text
실행 대기 프로세스
P1, P2, P3
     ↓
운영체제가 실행 순서 결정
     ↓
CPU에서 실행
```

대표적인 스케줄링 방식:

| 방식 | 설명 |
|---|---|
| FCFS | 먼저 들어온 프로세스부터 실행 |
| SJF | 실행 시간이 짧은 프로세스부터 실행 |
| Round Robin | 일정 시간씩 번갈아 실행 |
| Priority | 우선순위가 높은 프로세스부터 실행 |

---

### 2.2 메모리 관리

프로그램이 실행되려면 저장장치에 있던 코드와 데이터가 메모리에 올라와야 한다.

운영체제는 다음을 담당한다.

- 프로세스별 메모리 공간 할당
- 사용이 끝난 메모리 회수
- 다른 프로세스의 메모리 접근 방지
- 논리 주소와 물리 주소 변환
- 가상 메모리 관리

---

### 2.3 프로세스 관리

- **프로그램**: 저장장치에 존재하는 실행 파일
- **프로세스**: 메모리에 올라가 실행 중인 프로그램

```text
프로그램
저장장치에 존재하는 정적인 파일

프로세스
메모리에 올라가 CPU에서 실행 중인 상태
```

프로세스의 대표적인 상태:

```text
생성 → 준비 → 실행 → 대기 → 준비 → 종료
```

| 상태 | 의미 |
|---|---|
| 생성 | 프로세스가 만들어지는 중 |
| 준비 | CPU 할당을 기다리는 상태 |
| 실행 | CPU를 사용 중인 상태 |
| 대기 | 입출력 완료 등 특정 사건을 기다리는 상태 |
| 종료 | 실행을 마치고 자원을 반환하는 상태 |

---

### 2.4 입출력장치 관리

키보드, 마우스, 모니터, 프린터 등은 각각 동작 방식이 다르다.  
운영체제는 **디바이스 드라이버**를 통해 장치를 제어한다.

```text
응용 프로그램
    ↓
운영체제
    ↓
디바이스 드라이버
    ↓
하드웨어 장치
```

---

### 2.5 파일 시스템 관리

운영체제는 저장장치의 데이터를 파일과 디렉터리 형태로 관리한다.

주요 기능:

- 파일 생성·삭제
- 파일 읽기·쓰기
- 디렉터리 관리
- 접근 권한 설정
- 저장 공간 관리

---

### 2.6 보안 및 사용자 관리

운영체제는 사용자와 프로그램의 접근 권한을 제어한다.

예시:

- 사용자 로그인
- 관리자 권한 관리
- 파일 읽기·쓰기 권한
- 프로세스 간 메모리 접근 제한

---

## 3. 운영체제의 구조

```text
┌──────────────────────────┐
│ 사용자                    │
├──────────────────────────┤
│ 응용 프로그램             │
├──────────────────────────┤
│ 셸 / GUI                  │
├──────────────────────────┤
│ 시스템 콜                │
├──────────────────────────┤
│ 커널                      │
│ CPU·메모리·파일·장치 관리 │
├──────────────────────────┤
│ 하드웨어                  │
└──────────────────────────┘
```

### 3.1 커널

운영체제의 핵심 부분이다.  
하드웨어 자원을 직접 관리한다.

주요 기능:

- 프로세스 관리
- CPU 스케줄링
- 메모리 관리
- 파일 시스템 관리
- 입출력장치 관리

### 3.2 셸

사용자 명령을 해석해 운영체제에 전달하는 프로그램이다.

```bash
cd project
mkdir test
python main.py
```

대표적인 셸:

- Windows 명령 프롬프트
- PowerShell
- Bash
- Zsh

GUI도 넓은 의미에서는 사용자와 운영체제 사이의 인터페이스 역할을 한다.

### 3.3 시스템 콜

응용 프로그램이 운영체제의 기능을 요청하는 방법이다.

```text
응용 프로그램
    ↓ 시스템 콜
커널
    ↓
하드웨어 처리
```

대표적인 시스템 콜:

| 기능 | 예시 |
|---|---|
| 프로세스 관리 | `fork`, `exec`, `exit` |
| 파일 관리 | `open`, `read`, `write`, `close` |
| 메모리 관리 | `mmap`, `brk` |
| 통신 | `socket`, `send`, `recv` |

## 4. 사용자 모드와 커널 모드

CPU는 권한 수준에 따라 두 가지 모드로 동작한다.

### 사용자 모드

일반 응용 프로그램이 실행되는 모드다.

- 하드웨어 직접 접근 불가
- 중요한 명령 실행 불가
- 오류 발생 시 시스템 전체 영향 제한

### 커널 모드

운영체제 커널이 실행되는 모드다.

- 모든 하드웨어 접근 가능
- CPU, 메모리, 장치 직접 제어
- 높은 권한 보유

```text
사용자 모드
    ↓ 시스템 콜
커널 모드
    ↓ 처리 완료
사용자 모드로 복귀
```

---

## 5. 인터럽트

인터럽트는 CPU가 현재 작업을 잠시 멈추고, 우선 처리해야 하는 사건을 처리하도록 만드는 신호다.

예시:

- 키보드 입력
- 마우스 클릭
- 디스크 입출력 완료
- 네트워크 데이터 수신
- 타이머 종료

```text
프로그램 실행
    ↓
인터럽트 발생
    ↓
현재 상태 저장
    ↓
인터럽트 처리
    ↓
기존 프로그램 실행 재개
```

### 시스템 콜과 인터럽트 비교

| 구분 | 시스템 콜 | 인터럽트 |
|---|---|---|
| 발생 주체 | 실행 중인 프로그램 | 하드웨어 또는 시스템 |
| 목적 | 운영체제 기능 요청 | 사건 발생 알림 |
| 예시 | 파일 읽기 요청 | 키보드 입력 발생 |

# 3.1.2 컴퓨터의 요소

컴퓨터는 크게 CPU, 메모리, 저장장치, 입출력장치, 시스템 버스로 구성된다.

```text
           ┌────────────┐
           │    CPU     │
           └─────┬──────┘
                 │
       ┌─────────┴─────────┐
       │    시스템 버스     │
       └───┬───────────┬───┘
           │           │
      ┌────▼────┐ ┌────▼──────┐
      │ 메모리   │ │ 입출력장치 │
      └─────────┘ └───────────┘
```

---

## 1. CPU

CPU는 명령어를 해석하고 실행하는 장치다.

### 1.1 제어장치

명령어를 해석하고 다른 장치의 동작을 제어한다.

### 1.2 산술논리연산장치

계산과 논리 연산을 수행한다.

예시:

- 덧셈, 뺄셈
- 크기 비교
- AND, OR, NOT 연산

### 1.3 레지스터

CPU 내부에 있는 매우 빠른 임시 저장 공간이다.

| 레지스터 | 역할 |
|---|---|
| 프로그램 카운터 | 다음에 실행할 명령어 주소 저장 |
| 명령어 레지스터 | 현재 실행 중인 명령어 저장 |
| 범용 레지스터 | 연산 대상과 결과 임시 저장 |
| 스택 포인터 | 현재 스택의 위치 저장 |

---

## 2. 명령어 처리 과정

CPU는 명령어를 반복해서 가져오고 실행한다.  
이를 **명령어 사이클**이라고 한다.

```text
인출 → 해석 → 실행 → 저장
```

| 단계 | 설명 |
|---|---|
| 인출 | 메모리에서 실행할 명령어를 가져옴 |
| 해석 | 명령어의 의미와 수행할 작업을 분석 |
| 실행 | 계산, 이동, 비교 등을 수행 |
| 저장 | 결과를 레지스터나 메모리에 저장 |

---

## 3. 메모리

메모리는 실행 중인 프로그램과 데이터를 저장한다.

CPU는 일반적으로 저장장치에 있는 프로그램을 직접 실행하지 못한다.

```text
SSD에 저장된 프로그램
        ↓
메모리에 적재
        ↓
CPU가 명령어 실행
```

---

## 4. 저장장치

프로그램과 데이터를 장기간 보관하는 장치다.

예시:

- HDD
- SSD
- USB 메모리

특징:

- 메모리보다 느림
- 용량이 큼
- 전원이 꺼져도 데이터 유지

---

## 5. 입출력장치

사용자 또는 외부 환경과 데이터를 주고받는 장치다.

### 입력장치

- 키보드
- 마우스
- 마이크
- 카메라

### 출력장치

- 모니터
- 스피커
- 프린터

---

## 6. 시스템 버스

컴퓨터 내부 구성 요소 사이에서 데이터를 전달하는 통로다.

| 버스 | 역할 |
|---|---|
| 데이터 버스 | 실제 데이터를 전달 |
| 주소 버스 | 데이터가 저장된 위치를 전달 |
| 제어 버스 | 읽기, 쓰기, 인터럽트 등의 제어 신호 전달 |

```text
CPU ─ 데이터 버스 ─ 메모리
CPU ─ 주소 버스 ─── 메모리
CPU ─ 제어 버스 ─── 메모리
```

# 핵심 정리

- 운영체제는 응용 프로그램과 하드웨어 사이에서 자원을 관리한다.
- 커널은 운영체제의 핵심이며 CPU, 메모리, 파일, 장치를 직접 관리한다.
- 시스템 콜은 응용 프로그램이 커널 기능을 요청하는 방법이다.
- 사용자 모드는 권한이 제한되고, 커널 모드는 하드웨어를 직접 제어할 수 있다.
- 인터럽트는 CPU에 사건 발생을 알리는 신호다.
- CPU는 제어장치, 산술논리연산장치, 레지스터로 구성된다.
- 명령어는 인출, 해석, 실행, 저장 순서로 처리된다.
- 시스템 버스는 데이터, 주소, 제어 신호를 전달한다.
