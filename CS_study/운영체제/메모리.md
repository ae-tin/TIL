# 3.2.1 메모리 계층

## 1. 메모리 계층이란?

컴퓨터의 저장장치는 속도, 용량, 가격이 서로 다르다.

```text
빠름 · 비쌈 · 용량 작음
          ▲
       레지스터
         캐시
       주기억장치
      보조기억장치
          ▼
느림 · 저렴 · 용량 큼
```

| 계층 | 속도 | 용량 | 비용 | 휘발성 |
|---|---:|---:|---:|---|
| 레지스터 | 가장 빠름 | 매우 작음 | 매우 높음 | 휘발성 |
| 캐시 | 매우 빠름 | 작음 | 높음 | 휘발성 |
| 주기억장치 | 보통 | 중간 | 보통 | 휘발성 |
| SSD/HDD | 느림 | 큼 | 낮음 | 비휘발성 |

상위 계층일수록 빠르지만 용량이 작고 가격이 비싸다.  
하위 계층일수록 느리지만 용량이 크고 가격이 저렴하다.

---

## 2. 레지스터

CPU 내부에 존재하는 가장 빠른 저장 공간이다.

- CPU가 즉시 사용할 데이터 저장
- 연산 대상과 결과 임시 저장
- 용량이 매우 작음

```text
3 + 5 계산

레지스터 A ← 3
레지스터 B ← 5
ALU 계산
레지스터 C ← 8
```

---

## 3. 캐시 메모리

CPU와 주기억장치 사이의 속도 차이를 줄이기 위한 메모리다.

```text
CPU ↔ 캐시 ↔ 주기억장치
```

### 캐시 히트

CPU가 필요한 데이터가 캐시에 존재하는 경우다.

```text
CPU → 캐시에서 즉시 데이터 획득
```

### 캐시 미스

CPU가 필요한 데이터가 캐시에 없는 경우다.

```text
CPU → 캐시 확인 → 없음
                  ↓
              메모리 접근
```

캐시 미스가 자주 발생하면 메모리 접근 횟수가 증가해 프로그램 실행 속도가 느려진다.

---

## 4. 캐시 계층

일반적으로 캐시는 L1, L2, L3로 구분된다.

| 캐시 | 특징 |
|---|---|
| L1 | 가장 빠르고 용량이 가장 작음 |
| L2 | L1보다 느리지만 용량이 큼 |
| L3 | 여러 CPU 코어가 공유하는 경우가 많음 |

```text
CPU 코어
  ↓
L1 캐시
  ↓
L2 캐시
  ↓
L3 캐시
  ↓
RAM
```

---

## 5. 지역성

캐시는 프로그램이 특정 데이터나 명령어를 반복해서 사용하는 성질을 활용한다.  
이를 **지역성의 원리**라고 한다.

### 5.1 시간 지역성

최근 사용한 데이터가 가까운 미래에 다시 사용될 가능성이 높다는 성질이다.

```python
for _ in range(100):
    total += value
```

`total`, `value`가 반복해서 사용된다.

### 5.2 공간 지역성

특정 메모리 주소를 사용하면 그 주변 주소도 사용할 가능성이 높다는 성질이다.

```python
for i in range(len(arr)):
    print(arr[i])
```

배열의 연속된 데이터를 순서대로 접근한다.

---

## 6. 주기억장치와 보조기억장치

### 주기억장치

일반적으로 RAM을 의미한다.

- CPU가 직접 접근 가능
- 실행 중인 프로그램 저장
- 전원이 꺼지면 데이터 소멸

### 보조기억장치

SSD나 HDD를 의미한다.

- 프로그램과 데이터를 장기 보관
- 주기억장치보다 속도가 느림
- 전원이 꺼져도 데이터 유지

```text
보조기억장치
프로그램 장기 저장
      ↓ 적재
주기억장치
실행 중인 프로그램 저장
      ↓ 접근
CPU
명령어 실행
```

# 3.2.2 메모리 관리

## 1. 메모리 주소

메모리의 각 공간에는 고유한 주소가 있다.

```text
주소      값
1000      10
1001      20
1002      30
```

CPU는 메모리 주소를 이용해 데이터를 읽고 쓴다.

---

## 2. 논리 주소와 물리 주소

### 논리 주소

프로세스가 사용하는 가상의 주소다.

### 물리 주소

실제 RAM에 존재하는 주소다.

운영체제와 MMU가 논리 주소를 물리 주소로 변환한다.

```text
프로세스의 논리 주소
        ↓
       MMU
        ↓
실제 메모리의 물리 주소
```

MMU(Memory Management Unit)는 주소 변환을 담당하는 하드웨어다.

---

## 3. 프로세스의 메모리 구조

일반적인 프로세스는 다음과 같은 영역으로 구성된다.

```text
높은 주소
┌───────────────┐
│ Stack         │ 함수 호출, 지역 변수
│      ↓        │
├───────────────┤
│ 빈 공간       │
├───────────────┤
│      ↑        │
│ Heap          │ 동적 메모리
├───────────────┤
│ Data          │ 전역 변수, 정적 변수
├───────────────┤
│ Code/Text     │ 실행할 명령어
└───────────────┘
낮은 주소
```

### 코드 영역

실행할 프로그램 명령어가 저장된다.

### 데이터 영역

전역 변수와 정적 변수가 저장된다.

### 힙 영역

프로그램 실행 중 동적으로 할당한 메모리가 저장된다.

```c
int *arr = malloc(sizeof(int) * 100);
```

### 스택 영역

함수 호출 정보와 지역 변수가 저장된다.

```python
def add(a, b):
    result = a + b
    return result
```

---

## 4. 연속 메모리 할당

프로세스에 연속된 메모리 공간을 할당하는 방식이다.

```text
메모리
┌───────────┐
│ 운영체제   │
├───────────┤
│ 프로세스 A │
├───────────┤
│ 프로세스 B │
├───────────┤
│ 빈 공간    │
└───────────┘
```

구조는 단순하지만 메모리 공간이 잘게 나뉘는 단편화 문제가 발생할 수 있다.

---

## 5. 메모리 단편화

### 5.1 내부 단편화

할당받은 공간이 실제 필요한 공간보다 커서 내부에 낭비가 생기는 현상이다.

```text
할당 크기: 8KB
실제 사용: 6KB

[사용 6KB][낭비 2KB]
```

### 5.2 외부 단편화

전체 빈 공간은 충분하지만 여러 곳으로 흩어져 있어 연속된 공간을 할당하지 못하는 현상이다.

```text
[사용][빈 2KB][사용][빈 3KB][사용][빈 2KB]

총 빈 공간은 7KB지만
연속된 5KB 공간은 없음
```

## 6. 페이징

메모리를 동일한 크기의 블록으로 나누어 관리하는 방식이다.

- 논리 메모리의 블록: **페이지**
- 물리 메모리의 블록: **프레임**
- 페이지와 프레임의 크기는 같음

```text
프로세스 페이지        물리 메모리 프레임

페이지 0 ─────────→ 프레임 3
페이지 1 ─────────→ 프레임 7
페이지 2 ─────────→ 프레임 1
```

프로세스를 반드시 연속된 물리 메모리에 배치할 필요가 없다.

### 페이지 테이블

각 페이지가 어느 프레임에 저장되어 있는지 기록한다.

| 페이지 번호 | 프레임 번호 |
|---:|---:|
| 0 | 3 |
| 1 | 7 |
| 2 | 1 |

주소 변환 과정:

```text
논리 주소
페이지 번호 + 페이지 내부 위치
          ↓
페이지 테이블 조회
          ↓
프레임 번호 + 페이지 내부 위치
          ↓
물리 주소
```

---

## 7. 세그멘테이션

프로그램을 의미 있는 논리 단위로 나누는 방식이다.

예시:

- 코드 세그먼트
- 데이터 세그먼트
- 힙 세그먼트
- 스택 세그먼트

```text
프로세스
├─ 코드 세그먼트
├─ 데이터 세그먼트
├─ 힙 세그먼트
└─ 스택 세그먼트
```

### 페이징과 세그멘테이션 비교

| 구분 | 페이징 | 세그멘테이션 |
|---|---|---|
| 분할 기준 | 고정 크기 | 논리적 단위 |
| 블록 크기 | 동일 | 서로 다름 |
| 외부 단편화 | 거의 없음 | 발생 가능 |
| 내부 단편화 | 발생 가능 | 상대적으로 적음 |

---

## 8. 가상 메모리

프로그램 전체를 메모리에 올리지 않고 필요한 부분만 적재하는 기술이다.

```text
프로그램 전체
┌─────────────────┐
│ 페이지 0        │ → RAM
│ 페이지 1        │ → RAM
│ 페이지 2        │ → 저장장치
│ 페이지 3        │ → 저장장치
└─────────────────┘
```

장점:

- 실제 RAM보다 큰 프로그램 실행 가능
- 여러 프로그램을 동시에 실행 가능
- 메모리를 효율적으로 사용 가능

---

## 9. 요구 페이징

페이지가 실제로 필요해지는 시점에 메모리에 적재하는 방식이다.

CPU가 요청한 페이지가 메모리에 없으면 **페이지 폴트**가 발생한다.

```text
CPU가 페이지 요청
       ↓
메모리에 존재하는가?
   ├─ 예 → 바로 사용
   └─ 아니오 → 페이지 폴트
                 ↓
             저장장치에서 로드
                 ↓
             메모리에 적재
                 ↓
             명령어 재실행
```

페이지 폴트 자체는 오류가 아니라 정상적인 메모리 관리 과정이다.  
다만 너무 자주 발생하면 성능이 크게 저하된다.

---

## 10. 페이지 교체 알고리즘

메모리에 빈 프레임이 없으면 기존 페이지 중 하나를 내보내야 한다.

### 10.1 FIFO

가장 먼저 들어온 페이지를 제거한다.

- 구현이 단순함
- 자주 사용하는 페이지도 오래되었다는 이유로 제거될 수 있음

### 10.2 LRU

가장 오랫동안 사용하지 않은 페이지를 제거한다.

- 시간 지역성을 활용
- FIFO보다 실제 사용 패턴을 잘 반영하는 편

### 10.3 Optimal

앞으로 가장 오랫동안 사용되지 않을 페이지를 제거한다.

- 이론적으로 페이지 폴트가 가장 적음
- 미래의 접근 순서를 알아야 하므로 실제 구현은 어려움

| 알고리즘 | 교체 기준 | 특징 |
|---|---|---|
| FIFO | 가장 먼저 들어온 페이지 | 단순함 |
| LRU | 가장 오래 사용하지 않은 페이지 | 지역성 반영 |
| Optimal | 앞으로 가장 늦게 사용할 페이지 | 이론적 최적 |

---

## 11. 스래싱

페이지 폴트가 지나치게 많이 발생해 CPU가 프로그램 실행보다 페이지 교체에 더 많은 시간을 사용하는 현상이다.

```text
페이지 요청
  ↓
페이지 폴트
  ↓
디스크에서 로드
  ↓
다른 페이지 제거
  ↓
제거한 페이지 다시 필요
  ↓
페이지 폴트 반복
```

해결 방법:

- 동시에 실행하는 프로세스 수 감소
- 프로세스에 더 많은 프레임 할당
- 메모리 증설
- 지역성이 좋은 프로그램 구조 사용

# 핵심 비교

## 메모리와 저장장치

| 메모리 | 저장장치 |
|---|---|
| 속도가 빠름 | 상대적으로 느림 |
| 용량이 작음 | 용량이 큼 |
| 전원이 꺼지면 데이터 소멸 | 데이터 유지 |
| 실행 중인 프로그램 저장 | 프로그램 장기 보관 |

## 페이지와 프레임

| 페이지 | 프레임 |
|---|---|
| 논리 메모리의 블록 | 물리 메모리의 블록 |
| 프로세스 관점 | RAM 관점 |
| 페이지 테이블로 프레임과 연결 | 실제 데이터를 저장 |

## 내부 단편화와 외부 단편화

| 내부 단편화 | 외부 단편화 |
|---|---|
| 할당된 공간 내부가 남음 | 빈 공간이 여러 곳에 흩어짐 |
| 고정 크기 할당에서 발생하기 쉬움 | 연속 메모리 할당에서 발생하기 쉬움 |

# 핵심 정리

- 메모리 계층은 속도, 용량, 가격의 차이를 보완하기 위해 구성된다.
- 레지스터가 가장 빠르고, 보조기억장치가 가장 느리다.
- 캐시는 CPU와 RAM의 속도 차이를 줄인다.
- 캐시 효율은 시간 지역성과 공간 지역성을 이용한다.
- 논리 주소는 프로세스가 보는 주소고, 물리 주소는 실제 RAM 주소다.
- 페이징은 고정 크기, 세그멘테이션은 논리적 단위로 메모리를 나눈다.
- 가상 메모리는 필요한 페이지만 RAM에 올린다.
- 페이지 폴트는 필요한 페이지가 RAM에 없을 때 발생한다.
- 스래싱은 페이지 교체가 지나치게 반복되는 현상이다.
