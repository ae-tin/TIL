# 4.3 트랜잭션과 무결성

> 핵심: **데이터를 안전하게 변경하고, 올바른 상태를 유지하는 방법**

---

# 4.3.1 트랜잭션

## 1. 트랜잭션이란?

트랜잭션(Transaction)은 **데이터베이스의 상태를 변경하는 하나의 논리적 작업 단위**다.

예: 계좌 이체

```text
A 계좌에서 10,000원 차감
        ↓
B 계좌에 10,000원 증가
```

이 두 작업은 하나처럼 처리되어야 한다.

```text
A에서 돈은 빠졌는데
B에는 돈이 들어오지 않음
```

같은 상황이 생기면 안 된다.

---

## 2. COMMIT과 ROLLBACK

### COMMIT
트랜잭션의 변경사항을 최종 확정한다.

```sql
BEGIN;

UPDATE account
SET balance = balance - 10000
WHERE account_id = 1;

UPDATE account
SET balance = balance + 10000
WHERE account_id = 2;

COMMIT;
```

### ROLLBACK
트랜잭션의 변경사항을 취소하고 이전 상태로 되돌린다.

```sql
ROLLBACK;
```

---

## 3. ACID

트랜잭션의 핵심 특성은 ACID다.

### Atomicity — 원자성
트랜잭션은 **전부 성공하거나 전부 실패**해야 한다.

```text
All or Nothing
```

### Consistency — 일관성
트랜잭션 전후로 데이터베이스가 정의된 규칙을 만족해야 한다.

예:

```text
계좌 잔액은 음수가 될 수 없음
주문은 존재하는 회원을 참조해야 함
```

### Isolation — 격리성
동시에 실행되는 트랜잭션이 서로 방해하지 않는 것처럼 동작해야 한다.

### Durability — 지속성
COMMIT된 데이터는 장애가 발생해도 유지되어야 한다.

---

## 4. 트랜잭션 격리 수준

대표적인 격리 수준:

```text
READ UNCOMMITTED
READ COMMITTED
REPEATABLE READ
SERIALIZABLE
```

### READ UNCOMMITTED
다른 트랜잭션이 아직 COMMIT하지 않은 데이터도 읽을 수 있다.

- Dirty Read 가능

### READ COMMITTED
COMMIT된 데이터만 읽는다.

- Dirty Read 방지
- Non-Repeatable Read 가능

### REPEATABLE READ
같은 트랜잭션 안에서 같은 행을 반복 조회하면 같은 값을 보장한다.

- Dirty Read 방지
- Non-Repeatable Read 방지
- DBMS 구현에 따라 Phantom Read 가능

### SERIALIZABLE
가장 강한 격리 수준.

트랜잭션을 순차적으로 실행한 것처럼 동작한다.

- 안정성 높음
- 동시성 낮아질 수 있음

---

## 5. 대표적인 동시성 문제

### Dirty Read

다른 트랜잭션이 아직 COMMIT하지 않은 값을 읽는 현상.

```text
T1: balance 100 → 50
T2: balance 50 읽음
T1: ROLLBACK
```

T2는 실제로 확정되지 않은 값을 읽은 셈이다.

### Non-Repeatable Read

같은 트랜잭션 안에서 같은 행을 두 번 읽었는데 값이 달라지는 현상.

```text
T1: balance = 100 읽음
T2: balance = 200으로 수정 후 COMMIT
T1: 다시 읽음 → 200
```

### Phantom Read

같은 조건으로 조회했는데 행의 개수가 달라지는 현상.

```text
T1: age >= 20 조회 → 10명
T2: 20세 사용자 추가 후 COMMIT
T1: 다시 조회 → 11명
```

---

## 6. 격리 수준 비교

| 격리 수준 | Dirty Read | Non-Repeatable Read | Phantom Read |
|---|---|---|---|
| READ UNCOMMITTED | 가능 | 가능 | 가능 |
| READ COMMITTED | 방지 | 가능 | 가능 |
| REPEATABLE READ | 방지 | 방지 | 가능할 수 있음 |
| SERIALIZABLE | 방지 | 방지 | 방지 |

# 4.3.2 무결성

## 1. 무결성이란?

무결성(Integrity)은 **데이터가 정확하고 일관된 상태를 유지하는 성질**이다.

---

## 2. 개체 무결성

각 레코드는 유일하게 식별되어야 한다.

주로 기본 키(PK)가 담당한다.

```text
student_id PK
```

기본 키는:

- 중복 불가
- NULL 불가

---

## 3. 참조 무결성

외래 키는 실제로 존재하는 데이터를 참조해야 한다.

예:

```text
회원
member_id
1
2
```

```text
주문
order_id | member_id
10       | 1
11       | 3   ← 회원 3번이 없으면 문제
```

---

## 4. 도메인 무결성

속성은 정의된 값의 범위를 만족해야 한다.

예:

```text
age >= 0
rating BETWEEN 1 AND 5
gender IN ('M', 'F')
```

---

## 5. 사용자 정의 무결성

서비스의 비즈니스 규칙에 따른 조건.

예:

```text
재고는 0보다 작을 수 없음
종료 날짜는 시작 날짜보다 빠를 수 없음
주문 금액은 음수가 될 수 없음
```

---

## 6. SQL 제약조건

대표적인 제약조건:

```text
PRIMARY KEY
FOREIGN KEY
UNIQUE
NOT NULL
CHECK
DEFAULT
```

예:

```sql
CREATE TABLE member (
    member_id BIGINT PRIMARY KEY,
    email VARCHAR(255) UNIQUE NOT NULL,
    age INT CHECK (age >= 0)
);
```

# 트랜잭션과 무결성 관계

```text
무결성
= 데이터가 지켜야 할 규칙

트랜잭션
= 데이터를 변경하면서 그 규칙을 안전하게 유지하는 작업 단위
```

# 면접 질문

## Q1. 트랜잭션이란?
여러 DB 연산을 하나의 논리적 작업 단위로 묶은 것이다.

## Q2. ACID를 설명해 주세요.
- Atomicity: 전부 성공 또는 전부 실패
- Consistency: 데이터 규칙 유지
- Isolation: 트랜잭션 간 간섭 제어
- Durability: COMMIT 결과 영구 유지

## Q3. Dirty Read란?
다른 트랜잭션이 아직 COMMIT하지 않은 값을 읽는 현상이다.

## Q4. 무결성의 종류는?
개체 무결성, 참조 무결성, 도메인 무결성, 사용자 정의 무결성.

```text
ROLLBACK
= 변경 취소

```
