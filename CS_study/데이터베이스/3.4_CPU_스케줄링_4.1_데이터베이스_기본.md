# 3.4 CPU 스케줄링 알고리즘

CPU 스케줄링은 **준비 상태(Ready)에 있는 프로세스들 중 어떤 프로세스에게 CPU를 할당할지 결정하는 것**이다.

운영체제는 여러 프로세스가 동시에 실행되는 것처럼 보이게 하기 위해 CPU 사용 순서를 정한다.

## 스케줄링의 주요 목표

- CPU 이용률 최대화
- 처리량(Throughput) 증가
- 반환 시간(Turnaround Time) 감소
- 대기 시간(Waiting Time) 감소
- 응답 시간(Response Time) 감소
- 특정 프로세스가 무한히 기다리는 기아(Starvation) 방지

## 주요 용어

### 반환 시간
프로세스가 도착해서 완전히 종료될 때까지 걸린 시간.

```text
반환 시간 = 종료 시간 - 도착 시간
```

### 대기 시간
프로세스가 준비 큐에서 CPU를 기다린 총 시간.

```text
대기 시간 = 반환 시간 - 실제 CPU 실행 시간
```

### 응답 시간
프로세스가 요청된 뒤 **처음 CPU를 할당받기까지** 걸린 시간.

---

# 3.4.1 비선점형 방식

비선점형(Non-preemptive)은 **한 프로세스가 CPU를 할당받으면 스스로 CPU를 반납할 때까지 다른 프로세스가 빼앗을 수 없는 방식**이다.

보통 다음 상황에서 CPU를 반납한다.

- 프로세스 종료
- I/O 요청
- 대기 상태로 전환

## FCFS

**First Come First Served**

먼저 도착한 프로세스를 먼저 실행한다.

```text
도착 순서
P1 → P2 → P3

실행 순서
P1 → P2 → P3
```

### 장점

- 구현이 매우 단순
- 공정하게 도착 순서대로 처리

### 단점

- 실행 시간이 긴 프로세스가 앞에 오면 뒤 프로세스가 오래 기다림
- 평균 대기 시간이 커질 수 있음

### Convoy Effect

긴 작업 하나 때문에 짧은 작업들이 뒤에서 줄줄이 기다리는 현상.

```text
P1: 20초
P2: 1초
P3: 1초

P1 → P2 → P3
```

P2, P3는 짧은 작업인데도 P1 때문에 오래 기다린다.

---

## SJF

**Shortest Job First**

CPU 실행 시간이 가장 짧은 프로세스를 먼저 실행한다.

```text
P1 = 8
P2 = 3
P3 = 5

실행 순서
P2 → P3 → P1
```

### 장점

- 평균 대기 시간을 최소화하는 데 유리

### 단점

- 실제 CPU 실행 시간을 미리 정확히 알기 어려움
- 긴 작업이 계속 밀릴 수 있음
- 기아 상태 가능

### 기아(Starvation)

짧은 작업이 계속 들어오면 긴 작업이 계속 뒤로 밀려 실행되지 못할 수 있다.

---

## 우선순위 스케줄링

각 프로세스에 우선순위를 부여하고 우선순위가 높은 프로세스를 먼저 실행한다.

비선점형으로 구현하면 현재 실행 중인 프로세스는 끝날 때까지 계속 실행한다.

### 문제점

낮은 우선순위 프로세스의 기아 발생 가능.

### 해결

**Aging**

오래 기다린 프로세스의 우선순위를 점점 높여준다.

---

# 3.4.2 선점형 방식

선점형(Preemptive)은 **실행 중인 프로세스라도 운영체제가 CPU를 강제로 회수할 수 있는 방식**이다.

예:

- 타임 슬라이스 만료
- 더 높은 우선순위 프로세스 도착
- 더 짧은 작업 도착

장점은 응답성이 좋다는 것이고, 단점은 문맥 교환(Context Switch)이 자주 발생할 수 있다는 점이다.

---

## Round Robin

각 프로세스에 일정 시간인 **Time Quantum**을 부여한다.

시간이 끝나면 CPU를 빼앗고 준비 큐의 뒤로 보낸다.

```text
Time Quantum = 2

P1 → P2 → P3 → P1 → P2 ...
```

### 장점

- 모든 프로세스가 CPU를 번갈아 사용
- 응답 시간이 짧음
- 대화형 시스템에 적합

### 단점

- Time Quantum이 너무 작으면 문맥 교환이 많아짐
- 너무 크면 FCFS와 비슷해짐

```text
Quantum 너무 작음
→ Context Switch 증가

Quantum 너무 큼
→ FCFS와 유사
```

---

## SRTF

**Shortest Remaining Time First**

SJF의 선점형 버전.

현재 실행 중인 프로세스보다 **남은 실행 시간이 더 짧은 프로세스가 들어오면 CPU를 빼앗는다.**

```text
P1 실행 중: 남은 시간 7
P2 도착: 실행 시간 2

→ P1 중단
→ P2 실행
```

### 장점

- 평균 대기 시간을 줄이는 데 유리

### 단점

- 실행 시간 예측 필요
- 긴 프로세스 기아 가능
- 문맥 교환 증가 가능

---

## 선점형 우선순위 스케줄링

더 높은 우선순위 프로세스가 도착하면 현재 실행 중인 프로세스를 중단하고 CPU를 할당한다.

### 문제점

- 낮은 우선순위 프로세스 기아

### 해결

- Aging

---

## 멀티레벨 큐

프로세스를 성격에 따라 여러 큐로 나눈다.

예:

```text
Queue 1: 시스템 프로세스
Queue 2: 대화형 프로세스
Queue 3: 배치 프로세스
```

큐마다 서로 다른 스케줄링 알고리즘을 사용할 수 있다.

---

## 멀티레벨 피드백 큐

멀티레벨 큐와 비슷하지만 **프로세스가 큐 사이를 이동할 수 있다.**

예:

```text
처음: 높은 우선순위 큐
↓
CPU를 오래 사용
↓
낮은 우선순위 큐로 이동
```

짧은 작업과 대화형 작업을 빠르게 처리하면서 긴 작업도 실행할 수 있도록 설계한다.

---

# 비선점형 vs 선점형

| 구분 | 비선점형 | 선점형 |
|---|---|---|
| CPU 회수 | 강제로 회수 불가 | 강제로 회수 가능 |
| 문맥 교환 | 적음 | 상대적으로 많음 |
| 응답성 | 낮을 수 있음 | 좋음 |
| 구현 | 비교적 단순 | 상대적으로 복잡 |
| 대표 알고리즘 | FCFS, SJF | RR, SRTF |

# 4장 데이터베이스

# 4.1 데이터베이스의 기본

데이터베이스(Database)는 **여러 사용자가 공유하고 사용할 수 있도록 체계적으로 저장한 데이터의 집합**이다.

DBMS(Database Management System)는 데이터베이스를 생성, 조회, 수정, 삭제하고 관리하는 소프트웨어다.

대표 DBMS:

- MySQL
- PostgreSQL
- Oracle
- SQL Server

---

# 4.1.1 엔터티

엔터티(Entity)는 **현실 세계에서 독립적으로 구분할 수 있는 대상**이다.

예:

- 학생
- 교수
- 상품
- 주문
- 회원

```text
학생
├─ 학번
├─ 이름
├─ 학과
└─ 학년
```

여기서 `학생`이 엔터티다.

## 엔터티의 특징

- 식별 가능해야 함
- 업무에서 관리할 필요가 있어야 함
- 여러 속성을 가질 수 있음
- 다른 엔터티와 관계를 맺을 수 있음

---

# 4.1.2 릴레이션

릴레이션(Relation)은 관계형 데이터베이스에서 **데이터를 행과 열 형태로 표현한 테이블**이다.

```text
학생 테이블

학번 | 이름 | 학과
----|------|-----
1   | 철수 | 컴공
2   | 영희 | 전자
```

일반적으로 릴레이션을 테이블과 거의 같은 의미로 사용한다.

## 관련 용어

```text
릴레이션 = 테이블
튜플 = 행
속성 = 열
```

---

# 4.1.3 속성

속성(Attribute)은 **엔터티가 가지는 특징이나 정보**다.

예를 들어 학생 엔터티:

```text
학생
├─ 학번
├─ 이름
├─ 전공
└─ 학년
```

여기서 학번, 이름, 전공, 학년이 속성이다.

관계형 DB에서는 보통 테이블의 **컬럼(Column)**에 해당한다.

---

# 4.1.4 도메인

도메인(Domain)은 **하나의 속성이 가질 수 있는 값의 범위나 집합**이다.

예:

```text
학년의 도메인
{1, 2, 3, 4}

성별의 도메인
{'M', 'F'}

나이의 도메인
0 이상의 정수
```

도메인은 데이터의 무결성을 유지하는 데 도움을 준다.

---

# 4.1.5 필드와 레코드

## 필드

필드(Field)는 테이블의 각 속성에 해당하는 데이터 항목이다.

```text
학생 테이블

학번 | 이름 | 학과
```

학번, 이름, 학과가 각각 필드에 해당한다.

## 레코드

레코드(Record)는 하나의 객체에 대한 데이터 묶음이다.

```text
1 | 철수 | 컴퓨터공학
```

이 한 행 전체가 하나의 레코드다.

관계형 DB에서는 레코드를 **튜플(Tuple)**이라고도 한다.

```text
필드 ≈ 컬럼 ≈ 속성
레코드 ≈ 행 ≈ 튜플
```

---

# 4.1.6 관계

관계(Relationship)는 **엔터티와 엔터티 사이의 연관성**이다.

대표적인 관계는 세 가지다.

## 1:1 관계

한 엔터티가 다른 엔터티 하나와만 연결된다.

```text
사람 1 ─── 1 여권
```

## 1:N 관계

하나의 엔터티가 여러 엔터티와 연결된다.

```text
부서 1 ─── N 직원
```

## N:M 관계

여러 엔터티가 서로 여러 개와 연결된다.

```text
학생 N ─── M 강의
```

관계형 데이터베이스에서는 보통 중간 테이블을 만들어 해결한다.

```text
학생
   \
    수강
   /
강의
```

예:

```text
학생
- student_id

강의
- course_id

수강
- student_id
- course_id
```

---

# 4.1.7 키

키(Key)는 **테이블에서 레코드를 식별하거나 테이블 간 관계를 연결하기 위해 사용하는 속성**이다.

## 기본 키

Primary Key, PK

각 레코드를 **유일하게 식별하는 키**.

조건:

- 중복 불가
- NULL 불가

## 후보 키

Candidate Key

기본 키가 될 수 있는 후보.

조건:

- 유일성
- 최소성

## 슈퍼 키

Super Key

레코드를 유일하게 식별할 수 있는 속성 또는 속성 집합.

```text
슈퍼 키
  ↓ 최소성 만족
후보 키
  ↓ 하나 선택
기본 키
```

## 대체 키

Alternate Key

후보 키 중 기본 키로 선택되지 않은 키.

## 외래 키

Foreign Key, FK

다른 테이블의 기본 키를 참조하는 키.

```text
부서
department_id (PK)
name
```

```text
직원
employee_id (PK)
name
department_id (FK)
```

## 복합 키

Composite Key

두 개 이상의 속성을 결합해 만든 키.

```text
(student_id, course_id)
```

---

# 키 종류 정리

| 키 | 의미 |
|---|---|
| 슈퍼 키 | 레코드를 유일하게 식별할 수 있는 속성 집합 |
| 후보 키 | 슈퍼 키 중 최소성을 만족 |
| 기본 키 | 후보 키 중 대표로 선택된 키 |
| 대체 키 | 후보 키 중 기본 키로 선택되지 않은 키 |
| 외래 키 | 다른 테이블의 키를 참조 |
| 복합 키 | 여러 속성으로 구성된 키 |

# 면접에서 자주 나오는 질문

## Q1. 선점형과 비선점형의 차이는?

비선점형은 프로세스가 CPU를 자발적으로 반납할 때까지 다른 프로세스가 CPU를 빼앗을 수 없다. 선점형은 운영체제가 실행 중인 프로세스에서 CPU를 강제로 회수할 수 있다.

## Q2. Round Robin의 Time Quantum이 너무 작으면?

문맥 교환이 지나치게 많이 발생해서 오버헤드가 증가한다.

## Q3. SJF의 단점은?

실제 실행 시간을 미리 알기 어렵고, 긴 작업이 계속 뒤로 밀리는 기아 상태가 발생할 수 있다.

## Q4. 엔터티와 속성의 차이는?

엔터티는 관리 대상 자체이고, 속성은 그 엔터티가 가지는 특징이다.

## Q5. 기본 키와 외래 키의 차이는?

기본 키는 자기 테이블의 레코드를 유일하게 식별한다. 외래 키는 다른 테이블의 기본 키 등을 참조하여 테이블 간 관계를 표현한다.

## Q6. 후보 키와 슈퍼 키의 차이는?

둘 다 레코드를 유일하게 식별할 수 있지만, 후보 키는 불필요한 속성을 제거한 최소성을 만족한다.

## Q7. N:M 관계는 관계형 DB에서 어떻게 구현하는가?

중간 테이블을 생성하고 양쪽 테이블의 기본 키를 외래 키로 저장한다.

# 복습 체크리스트

- [ ] CPU 스케줄링의 목적을 설명할 수 있다.
- [ ] 반환 시간, 대기 시간, 응답 시간의 차이를 안다.
- [ ] 선점형과 비선점형을 구분할 수 있다.
- [ ] FCFS의 Convoy Effect를 설명할 수 있다.
- [ ] SJF와 SRTF의 차이를 설명할 수 있다.
- [ ] Round Robin에서 Time Quantum의 역할을 안다.
- [ ] 기아 상태와 Aging을 설명할 수 있다.
- [ ] 엔터티, 릴레이션, 속성, 도메인의 차이를 안다.
- [ ] 필드와 레코드를 구분할 수 있다.
- [ ] 1:1, 1:N, N:M 관계를 구분할 수 있다.
- [ ] 기본 키, 후보 키, 슈퍼 키의 차이를 설명할 수 있다.
- [ ] 외래 키가 왜 필요한지 설명할 수 있다.
