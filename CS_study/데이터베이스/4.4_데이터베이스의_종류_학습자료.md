# 4.4 데이터베이스의 종류

> 핵심: **데이터 구조와 서비스 요구사항에 따라 어떤 DB를 선택할 것인가**

---

# 4.4.1 관계형 데이터베이스

## 1. 관계형 데이터베이스란?

관계형 데이터베이스(RDB)는 데이터를 **행과 열로 구성된 테이블 형태**로 저장한다.

대표 DBMS:

- MySQL
- PostgreSQL
- Oracle
- SQL Server
- MariaDB

---

## 2. 기본 구조

```text
회원

member_id | name | email
----------|------|----------------
1         | 철수 | a@example.com
2         | 영희 | b@example.com
```

```text
주문

order_id | member_id | amount
---------|-----------|-------
100      | 1         | 50000
101      | 1         | 30000
```

`member_id`를 통해 두 테이블이 연결된다.

---

## 3. 관계형 DB의 특징

- 테이블 기반 구조
- 명확한 스키마
- SQL 사용
- PK/FK로 관계 표현
- JOIN 지원
- 트랜잭션과 ACID 지원
- 데이터 무결성 관리에 강함

---

## 4. SQL 예시

```sql
SELECT *
FROM member
WHERE member_id = 1;
```

JOIN:

```sql
SELECT m.name, o.amount
FROM member m
JOIN orders o
  ON m.member_id = o.member_id;
```

---

## 5. 관계형 DB가 적합한 경우

- 데이터 구조가 명확함
- 테이블 간 관계가 중요함
- 트랜잭션 안정성이 중요함
- 데이터 무결성을 강하게 관리해야 함
- 복잡한 JOIN과 집계가 필요함

예:

```text
은행
쇼핑몰 주문
회계
ERP
예약 시스템
회원 관리
```

---

## 6. 장점

- 데이터 구조가 명확
- SQL 생태계가 성숙
- 트랜잭션 처리에 강함
- 무결성 유지가 쉬움
- 복잡한 JOIN과 집계 가능

---

## 7. 단점

- 스키마 변경이 상대적으로 까다로움
- 비정형 데이터 처리에 불편할 수 있음
- 대규모 분산 확장이 복잡할 수 있음
- JOIN이 많고 데이터가 커지면 성능 비용이 커질 수 있음

---

# 4.4.2 NoSQL 데이터베이스

## 1. NoSQL이란?

NoSQL은 **Not Only SQL**의 의미로, 관계형 모델 이외의 여러 방식으로 데이터를 저장하는 DB를 통칭한다.

대표적인 특징:

- 유연한 스키마
- 수평 확장에 유리
- 대규모 분산 처리에 적합
- 특정 데이터 접근 패턴에 최적화

---

# 2. NoSQL의 주요 종류

## 2.1 Key-Value DB

가장 단순한 구조.

```text
key → value
```

예:

```text
"user:1" → {"name": "철수", "age": 20}
```

대표 DB:

- Redis
- DynamoDB의 일부 사용 방식

### 적합한 용도

- 캐시
- 세션
- 인증 토큰
- 실시간 랭킹
- 빠른 단순 조회

---

## 2.2 Document DB

JSON과 유사한 문서 형태로 저장한다.

대표 DB:

- MongoDB
- CouchDB

예:

```json
{
  "_id": 1,
  "name": "철수",
  "email": "a@example.com",
  "orders": [
    {"product": "키보드", "price": 50000},
    {"product": "마우스", "price": 30000}
  ]
}
```

### 장점

- 스키마가 유연함
- 객체 구조와 자연스럽게 대응
- 중첩 데이터 저장이 편함

### 적합한 용도

- 콘텐츠 관리
- 사용자 프로필
- 로그
- JSON 중심 서비스

---

## 2.3 Column-Family DB

컬럼 패밀리 단위로 데이터를 저장한다.

대표 DB:

- Cassandra
- HBase

### 특징

- 대규모 분산 처리
- 높은 쓰기 처리량
- 대규모 시계열/로그 데이터에 활용 가능

### 적합한 용도

- 로그
- 이벤트 데이터
- IoT 데이터
- 대규모 분산 시스템

---

## 2.4 Graph DB

노드와 엣지로 데이터를 표현한다.

대표 DB:

- Neo4j
- Amazon Neptune

예:

```text
[철수] ─ 친구 → [영희]
  │
  └ 구매 → [키보드]
```

### 적합한 용도

- 소셜 네트워크
- 추천 시스템
- 지식 그래프
- 관계 탐색
- Fraud Detection

---

# 3. RDB vs NoSQL

| 구분 | RDB | NoSQL |
|---|---|---|
| 데이터 구조 | 테이블 | Key-Value, Document, Graph 등 |
| 스키마 | 엄격 | 상대적으로 유연 |
| 관계 표현 | JOIN, FK | 모델에 따라 다름 |
| 트랜잭션 | 강함 | 제품에 따라 다름 |
| 확장 | 수직 확장 중심 | 수평 확장에 유리 |
| 복잡한 조회 | 강함 | 종류에 따라 제한적 |
| 적합한 데이터 | 구조화 데이터 | 대규모/비정형 데이터 |

---

# 4. 수직 확장과 수평 확장

## Scale Up

한 서버의 성능을 높이는 방식.

```text
CPU 8 Core
↓
CPU 32 Core
```

장점:

- 구조가 단순함

단점:

- 물리적 한계
- 비용 증가

---

## Scale Out

서버의 개수를 늘리는 방식.

```text
Server 1
Server 2
Server 3
Server 4
```

NoSQL 제품들은 분산 환경에서 Scale Out을 고려해 설계된 경우가 많다.

---

# 5. CAP 개념

분산 데이터베이스에서 자주 등장한다.

```text
C = Consistency
A = Availability
P = Partition Tolerance
```

네트워크 분할이 발생한 상황에서는 Consistency와 Availability를 동시에 완벽히 만족하기 어렵다는 개념이다.

실제 시스템에서는 단순히 하나를 영구적으로 포기한다기보다 서비스 특성에 따라 일관성과 가용성 수준을 조절한다.

---

# 6. DB 선택 예시

## 은행 송금

추천:

```text
RDB
```

이유:

- 트랜잭션 중요
- 정확한 잔액 관리
- 데이터 무결성 중요

---

## 캐시

추천:

```text
Redis
```

이유:

- 매우 빠른 Key-Value 조회
- TTL 지원

---

## 로그 저장

후보:

```text
Document DB
Column-Family DB
```

이유:

- 데이터 양이 큼
- 구조가 자주 변할 수 있음

---

## 소셜 네트워크 관계 탐색

추천:

```text
Graph DB
```

이유:

```text
친구의 친구
공통 친구
추천 관계
```

같은 관계 탐색에 유리하다.

---

# 7. 실무에서의 선택

NoSQL이 RDB보다 무조건 좋은 것도 아니고,
RDB가 NoSQL보다 무조건 좋은 것도 아니다.

핵심 기준:

```text
데이터 구조
+
조회 패턴
+
트랜잭션 요구
+
확장 방식
+
일관성 요구
```

실무에서는 여러 DB를 함께 쓰기도 한다.

예:

```text
MySQL
→ 회원, 주문

Redis
→ 캐시, 세션

Elasticsearch
→ 검색

Neo4j
→ 관계 탐색
```

이런 방식을 Polyglot Persistence라고 부르기도 한다.

# 면접 질문

## Q1. RDB와 NoSQL의 차이는?
RDB는 테이블과 관계 중심이고 스키마 및 트랜잭션에 강하다. NoSQL은 다양한 데이터 모델과 유연한 스키마, 수평 확장에 강점이 있다.

## Q2. NoSQL을 사용하는 이유는?
대규모 분산 처리, 유연한 스키마, 특정 조회 패턴 최적화, 수평 확장 등이 주요 이유다.

## Q3. Redis는 어떤 DB인가?
대표적인 인메모리 Key-Value 데이터 저장소다. 캐시, 세션, 분산 락, 랭킹 등에 활용된다.

## Q4. Graph DB는 언제 좋은가?
데이터 자체보다 데이터 사이의 관계 탐색이 중요한 경우 유리하다.

# 핵심 요약

```text
RDB
= 테이블 기반
= SQL
= JOIN
= 트랜잭션, 무결성에 강함

NoSQL
= 다양한 데이터 모델
= 유연한 스키마
= 분산 확장에 유리

NoSQL 종류
- Key-Value
- Document
- Column-Family
- Graph

DB 선택
= 데이터 구조 + 조회 패턴 + 트랜잭션 + 확장성
```
