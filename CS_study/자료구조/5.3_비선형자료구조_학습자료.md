# 5.3 비선형 자료 구조

비선형 자료 구조(Non-linear Data Structure)는 데이터가 일렬로 연결되지 않고, **계층적이거나 네트워크 형태로 연결되는 자료 구조**다.

```text
선형 자료 구조

A → B → C → D


비선형 자료 구조

      A
    /   \
   B     C
  / \     \
 D   E     F
```

대표적인 비선형 자료 구조

```text
Graph
Tree
Heap
Priority Queue
Map
Set
Hash Table
```

---

# 5.3.1 그래프
## Graph

그래프는 **정점(Vertex)과 간선(Edge)**으로 이루어진 자료 구조다.

```text
Vertex
→ 데이터 또는 객체

Edge
→ Vertex 사이의 관계
```

예

```text
A ─── B
│     │
│     │
C ─── D
```

```text
Vertex
→ A, B, C, D

Edge
→ A-B, A-C, B-D, C-D
```

---

## 그래프의 구성

그래프는 보통

```text
G = (V, E)
```

로 표현한다.

```text
V
→ Vertex 집합

E
→ Edge 집합
```

---

# 방향 그래프
## Directed Graph

간선에 방향이 존재한다.

```text
A → B → C
```

예

- SNS 팔로우
- 웹 페이지 링크
- 작업 의존성
- 도로의 일방통행

---

# 무방향 그래프
## Undirected Graph

간선에 방향이 없다.

```text
A ─ B
```

A와 B가 서로 연결되어 있음.

예

- 친구 관계
- 양방향 도로
- 컴퓨터 네트워크

---

# 가중치 그래프
## Weighted Graph

간선에 비용이나 거리가 존재한다.

```text
A ──5── B
│
3
│
C
```

예

```text
도로 거리
네트워크 비용
항공 요금
```

최단 경로 알고리즘에서 많이 사용된다.

---

# 그래프 표현 방법

대표적으로

```text
Adjacency Matrix
Adjacency List
```

두 가지를 사용한다.

---

## 인접 행렬
### Adjacency Matrix

정점 간 연결 여부를 2차원 배열로 저장.

그래프

```text
A ─ B
│
C
```

인접 행렬

```text
    A B C

A   0 1 1
B   1 0 0
C   1 0 0
```

공간 복잡도

```text
O(V²)
```

장점

- 두 정점의 연결 여부를 O(1)에 확인 가능

단점

- 간선이 적어도 O(V²) 메모리 필요

따라서 **Dense Graph**에 적합.

---

## 인접 리스트
### Adjacency List

각 정점마다 연결된 정점을 저장.

```text
A → [B, C]
B → [A]
C → [A]
```

공간 복잡도

```text
O(V + E)
```

장점

- 실제 존재하는 간선만 저장
- Sparse Graph에서 메모리 효율적

단점

- A와 B가 연결되어 있는지 확인하려면 A의 리스트를 탐색해야 함

---

# 그래프 탐색

대표적인 탐색 알고리즘

```text
DFS
BFS
```

---

## DFS
### Depth First Search

한 방향으로 최대한 깊게 탐색한다.

```text
A
├─ B
│  ├─ D
│  └─ E
└─ C
```

예

```text
A → B → D → E → C
```

주로

```text
Stack
또는
Recursion
```

을 사용한다.

시간 복잡도

```text
인접 리스트
→ O(V + E)

인접 행렬
→ O(V²)
```

---

## BFS
### Breadth First Search

가까운 정점부터 탐색한다.

```text
A
├─ B
│  ├─ D
│  └─ E
└─ C
```

예

```text
A → B → C → D → E
```

주로

```text
Queue
```

를 사용한다.

시간 복잡도

```text
인접 리스트
→ O(V + E)
```

BFS는 가중치가 없는 그래프에서 **최단 거리**를 구하는 데 사용할 수 있다.

---

# 그래프 활용

- 네트워크
- SNS 관계
- 지도 / 경로 탐색
- 추천 시스템
- 의존성 관계
- 지식 그래프
- 컴퓨터 네트워크
- 프로젝트 작업 순서

# 5.3.2 트리
## Tree

트리는 **계층적 구조를 표현하는 비선형 자료 구조**다.

그래프의 한 종류이며

```text
Cycle이 없고
모든 Node가 연결되어 있다.
```

```text
        A
      /   \
     B     C
    / \   / \
   D   E F   G
```

---

# 트리 용어

```text
Root
→ 가장 위의 Node

Parent
→ 현재 Node의 상위 Node

Child
→ 현재 Node의 하위 Node

Leaf
→ Child가 없는 Node

Depth
→ Root에서 해당 Node까지의 거리

Height
→ 해당 Node에서 가장 깊은 Leaf까지의 거리

Subtree
→ 특정 Node를 Root로 하는 작은 Tree
```

예

```text
        A       ← Root
      /   \
     B     C
    / \
   D   E         ← Leaf
```

```text
A
→ B와 C의 Parent

B
→ A의 Child
→ D와 E의 Parent
```

---

# 트리의 특징

정점이 N개인 트리는 간선이

```text
N - 1개
```

이다.

또한

```text
Cycle 없음
두 Node 사이의 경로가 하나뿐
```

이라는 특징을 가진다.

---

# 이진 트리
## Binary Tree

각 Node가 최대 2개의 Child를 가지는 Tree.

```text
        A
       / \
      B   C
     / \
    D   E
```

Child는 일반적으로

```text
Left Child
Right Child
```

로 구분한다.

---

# 완전 이진 트리
## Complete Binary Tree

마지막 Level을 제외하면 모두 채워져 있고,
마지막 Level은 왼쪽부터 채워진 Tree.

```text
        1
       / \
      2   3
     / \  /
    4  5 6
```

Heap이 대표적인 Complete Binary Tree다.

---

# 포화 이진 트리
## Full / Perfect Binary Tree

모든 Level이 완전히 채워진 Tree.

```text
        1
       / \
      2   3
     / \ / \
    4  5 6  7
```

---

# 이진 탐색 트리
## Binary Search Tree

각 Node에 대해

```text
Left Subtree
< 현재 Node

Right Subtree
> 현재 Node
```

규칙을 만족한다.

예

```text
        8
      /   \
     4     12
    / \   / \
   2   6 10 14
```

검색 과정

```text
10 검색

8
→ 10 > 8
→ 오른쪽

12
→ 10 < 12
→ 왼쪽

10 발견
```

---

# BST 시간 복잡도

균형이 잡혀 있다면

```text
검색 O(log N)
삽입 O(log N)
삭제 O(log N)
```

하지만 한쪽으로 치우치면

```text
1
 \
  2
   \
    3
     \
      4
```

사실상 Linked List처럼 된다.

따라서 최악의 경우

```text
O(N)
```

---

# 균형 이진 탐색 트리

BST가 한쪽으로 치우치는 문제를 해결하기 위해

```text
AVL Tree
Red-Black Tree
```

등이 사용된다.

검색/삽입/삭제를

```text
O(log N)
```

수준으로 유지한다.

---

# 트리 순회
## Tree Traversal

대표적으로

```text
Preorder
Inorder
Postorder
Level Order
```

가 있다.

트리

```text
        A
       / \
      B   C
     / \
    D   E
```

---

## 전위 순회
### Preorder

```text
Root → Left → Right
```

결과

```text
A B D E C
```

---

## 중위 순회
### Inorder

```text
Left → Root → Right
```

결과

```text
D B E A C
```

BST를 중위 순회하면 값이 **정렬된 순서**로 나온다.

---

## 후위 순회
### Postorder

```text
Left → Right → Root
```

결과

```text
D E B C A
```

---

## 레벨 순회
### Level Order

Level 단위로 탐색.

```text
A B C D E
```

Queue를 사용한다.

# 5.3.3 힙
## Heap

Heap은 **최댓값 또는 최솟값을 빠르게 찾기 위한 완전 이진 트리**다.

대표적으로

```text
Min Heap
Max Heap
```

이 있다.

---

# 최소 힙
## Min Heap

부모 Node가 Child보다 작거나 같다.

```text
Parent <= Child
```

예

```text
        1
       / \
      3   5
     / \
    7   9
```

Root에는 항상

```text
최솟값
```

이 위치한다.

---

# 최대 힙
## Max Heap

부모 Node가 Child보다 크거나 같다.

```text
Parent >= Child
```

예

```text
        9
       / \
      7   5
     / \
    3   1
```

Root에는 항상

```text
최댓값
```

이 존재한다.

---

# Heap의 중요한 특징

Heap은 **완전히 정렬된 자료 구조가 아니다.**

Min Heap이라고 해서

```text
1 2 3 4 5
```

순서로 저장되는 것은 아니다.

조건은 오직

```text
Parent <= Child
```

이다.

예

```text
        1
       / \
      5   2
     / \
    8   7
```

이것도 Min Heap이다.

---

# Heap의 배열 표현

Complete Binary Tree이므로 배열로 효율적으로 표현할 수 있다.

```text
        1
       / \
      3   5
     / \
    7   9
```

배열

```text
[1, 3, 5, 7, 9]
```

0-based index 기준

```text
Parent
→ (i - 1) // 2

Left Child
→ 2i + 1

Right Child
→ 2i + 2
```

---

# Heap 삽입

새 데이터를 마지막에 삽입한다.

```text
        1
       / \
      3   5
     / \
    7   9
```

2 삽입

```text
        1
       / \
      3   5
     / \  /
    7  9 2
```

부모와 비교하면서 위로 이동한다.

```text
2 < 5
→ Swap
```

```text
        1
       / \
      3   2
     / \  /
    7  9 5
```

이를

```text
Heapify Up
Sift Up
```

이라고 한다.

트리 높이가

```text
O(log N)
```

이므로 삽입도

```text
O(log N)
```

---

# Heap 삭제

Min Heap에서 최솟값 삭제

```text
Root 제거
```

마지막 Node를 Root로 이동.

```text
        9
       / \
      3   2
     /
    7
```

Child와 비교하면서 아래로 이동.

이를

```text
Heapify Down
Sift Down
```

이라고 한다.

시간 복잡도

```text
O(log N)
```

---

# Heap 시간 복잡도

| 연산 | 시간 복잡도 |
|---|---:|
| 최소/최대값 조회 | O(1) |
| 삽입 | O(log N) |
| Root 삭제 | O(log N) |
| 특정 값 검색 | O(N) |
| Heap 생성 | O(N) |

주의

Heap은 Root의 최소/최대값만 빠르게 찾는 구조이므로

```text
특정 값 검색
→ O(N)
```

이다.

---

# 5.3.4 우선순위 큐
## Priority Queue

Priority Queue는 먼저 들어온 데이터가 아니라 **우선순위가 높은 데이터부터 꺼내는 자료 구조**다.

일반 Queue

```text
FIFO
```

Priority Queue

```text
Priority가 높은 데이터 먼저 처리
```

---

# 예시

```text
Task A → Priority 3
Task B → Priority 1
Task C → Priority 5
```

Priority가 클수록 높은 경우

```text
C → A → B
```

순서로 처리.

---

# Priority Queue와 Heap

Priority Queue는 **자료 구조의 개념 또는 ADT(Abstract Data Type)**이고,
Heap은 이를 구현하는 대표적인 방법이다.

```text
Priority Queue
      ↓
구현 방법
      ↓
Heap
```

따라서

```text
Priority Queue = Heap
```

이라고 완전히 동일시하면 안 된다.

하지만 실제 구현에서는 대부분 Heap을 사용한다.

---

# Priority Queue 시간 복잡도

Heap 기반

| 연산 | 시간 복잡도 |
|---|---:|
| Top 조회 | O(1) |
| 삽입 | O(log N) |
| Top 삭제 | O(log N) |

---

# Python heapq

Python에서는

```python
import heapq
```

를 사용한다.

기본적으로

```text
Min Heap
```

이다.

```python
heapq.heappush(heap, x)
heapq.heappop(heap)
```

---

# Priority Queue 활용

- 작업 스케줄링
- 최단 경로 알고리즘
- Dijkstra
- Prim
- 최소 비용 문제
- Top K
- 가장 작은/큰 값 반복 추출

# 5.3.5 맵
## Map

Map은 데이터를

```text
Key → Value
```

형태로 저장하는 자료 구조다.

예

```text
"name" → "Kim"
"age"  → 30
"id"   → 1001
```

Key는 일반적으로 중복될 수 없다.

---

# Map의 핵심

```text
Key
→ 데이터를 식별

Value
→ 실제 데이터
```

예

```text
student_id → student_info
product_id → product
user_id → user
```

---

# Map 구현 방식

Map은 구현 방식에 따라 크게

```text
Tree-based Map
Hash-based Map
```

으로 나눌 수 있다.

---

## Tree Map

Balanced BST 등을 이용.

예

```text
Java TreeMap
C++ std::map
```

검색/삽입/삭제

```text
O(log N)
```

장점

```text
Key가 정렬되어 있음
```

따라서

```text
최솟값
최댓값
범위 검색
```

등에 유리하다.

---

## Hash Map

Hash Table 기반.

예

```text
Python dict
Java HashMap
C++ unordered_map
```

평균적으로

```text
검색 O(1)
삽입 O(1)
삭제 O(1)
```

장점

```text
빠른 Key Lookup
```

단점

```text
Key의 정렬 순서를 이용한 범위 검색에는 부적합
```

---

# Map 시간 복잡도 비교

| 종류 | 검색 | 삽입 | 삭제 | 정렬 |
|---|---:|---:|---:|---|
| Tree Map | O(log N) | O(log N) | O(log N) | O |
| Hash Map | 평균 O(1) | 평균 O(1) | 평균 O(1) | X |

---

# Map 활용

- 사용자 ID → 사용자 정보
- 단어 → 등장 횟수
- 설정 값 저장
- 캐시
- 데이터 Index
- Key 기반 검색

# 5.3.6 셋
## Set

Set은 **중복을 허용하지 않는 데이터 집합**이다.

예

```text
[1, 2, 2, 3, 3, 3]
```

Set으로 만들면

```text
{1, 2, 3}
```

---

# Set의 특징

```text
중복 제거
빠른 Membership Test
집합 연산
```

에 많이 사용된다.

---

# Membership Test

특정 값이 존재하는지 확인.

```python
x in s
```

```text
O(1)
```

---

## 차집합


# Map vs Set

Map

```text

```

Set

```text

```

즉 Set은 개념적으로

```text

```

처럼 이해할 수 있다.

# 5.3.7 해시 테이블
## Hash Table

Hash Table은 **Key를 Hash Function에 넣어 얻은 Hash 값을 이용해 데이터를 저장하고 검색하는 자료 구조**다.

```text
Key
 ↓
Hash Function
 ↓
Hash Value
 ↓
Index
 ↓
Bucket
```

---

# 기본 구조

예

```text
Key = "apple"
```

Hash Function

```text
hash("apple")
→ 127381
```

배열 크기가 10이라면

```text
127381 % 10
= 1
```

따라서

```text
Index 1
```

에 저장.

```text
0
1 → apple
2
3
4
...
```

---

# Hash Function

Hash Function은 Key를 특정 정수 값으로 변환한다.

좋은 Hash Function은

```text
계산이 빠르고
Hash 값이 고르게 분산되고
충돌이 적어야 한다.
```

---

# Hash Collision
## 해시 충돌

서로 다른 Key가 같은 Hash Index를 가지는 현상.

예

```text
hash("apple") % 10
→ 3

hash("banana") % 10
→ 3
```

```text
apple
banana

둘 다 Bucket 3
```

이를

```text
Hash Collision
```

이라고 한다.

---

# 충돌 해결 방법

대표적으로

```text
Separate Chaining
Open Addressing
```

이 있다.

---

## Separate Chaining
### 체이닝

같은 Bucket에 여러 데이터를 연결해서 저장.

```text
Bucket 0

Bucket 1
  ↓
apple → banana → orange

Bucket 2
```

Linked List나 Tree 등을 이용할 수 있다.

---

## Open Addressing
### 개방 주소법

충돌이 발생하면 다른 빈 Bucket을 찾는다.

대표적인 방법

```text
Linear Probing
Quadratic Probing
Double Hashing
```

---

# Linear Probing

충돌 발생 시 다음 칸을 확인.

```text
Index 3 충돌
 ↓
Index 4 확인
 ↓
비어 있으면 저장
```

---

# Load Factor
## 적재율

Hash Table에 데이터가 얼마나 차 있는지를 나타낸다.

```text
Load Factor

= 저장된 데이터 수 / Bucket 수
```

예

```text
Bucket 10개
Data 7개

Load Factor
= 0.7
```

Load Factor가 높아질수록

```text
Collision 증가
→ 성능 감소
```

할 가능성이 높다.

따라서 일정 수준 이상이면

```text
Resize
Rehash
```

를 수행한다.

---

# Rehashing

Hash Table의 크기를 늘리고 데이터를 다시 배치.

```text
기존 Table
Size = 8

      ↓

새 Table
Size = 16

      ↓

모든 Key를 다시 Hash
```

이 과정은 일시적으로

```text
O(N)
```

이 필요하다.

하지만 자주 발생하지 않기 때문에 삽입은 평균적으로

```text
Amortized O(1)
```

로 볼 수 있다.

---

# Hash Table 시간 복잡도

| 연산 | 평균 | 최악 |
|---|---:|---:|
| 검색 | O(1) | O(N) |
| 삽입 | O(1) | O(N) |
| 삭제 | O(1) | O(N) |

최악의 경우

```text
모든 Key가 같은 Bucket에 충돌
```

하면 Linked List처럼 되어

```text
O(N)
```

이 될 수 있다.

---

# Hash Table vs BST

| 특징 | Hash Table | Balanced BST |
|---|---|---|
| 검색 | 평균 O(1) | O(log N) |
| 삽입 | 평균 O(1) | O(log N) |
| 삭제 | 평균 O(1) | O(log N) |
| Key 정렬 | X | O |
| 범위 검색 | 불리 | 유리 |
| 최악 성능 | O(N) 가능 | O(log N) |

따라서

```text
정확한 Key 검색
→ Hash Table

정렬 / 범위 검색
→ Tree
```

이 유리하다.

---

# Map / Set / Hash Table 관계

이 세 개는 자주 혼동한다.

```text
Map
→ Key-Value를 저장하는 추상적 자료 구조

Set
→ 중복 없는 Key 집합

Hash Table
→ Map이나 Set을 구현하는 방법 중 하나
```

예

```text
Python dict
→ Hash Table 기반 Map

Python set
→ Hash Table 기반 Set
```

Tree를 이용해서도 Map과 Set을 구현할 수 있다.

```text
Tree Map
Tree Set
```

따라서

```text
Map != Hash Table
Set != Hash Table
```

이다.

Hash Table은 **구현 방식**에 가깝다.

---

# Heap vs Priority Queue

역시 자주 혼동한다.

```text
Priority Queue
→ 우선순위가 높은 데이터를 먼저 꺼내는 ADT

Heap
→ Priority Queue를 구현하는 대표적인 자료 구조
```

```text
Priority Queue
      ↓
    Heap
```

---

# Graph vs Tree

Tree는 Graph의 특수한 형태다.

Tree의 조건

```text
모든 Node가 연결
Cycle 없음
```

N개의 Node가 있다면

```text
Edge = N - 1
```

Graph는

```text
Cycle 가능
여러 경로 가능
방향 가능
Disconnected 가능
```

# 주요 시간 복잡도 정리

| 자료 구조 | 검색 | 삽입 | 삭제 | 주요 특징 |
|---|---:|---:|---:|---|
| Graph | 탐색 O(V+E) | - | - | 관계 표현 |
| BST | 평균 O(log N) | 평균 O(log N) | 평균 O(log N) | 정렬된 Tree |
| Heap | O(N) | O(log N) | O(log N) | 최소/최대값 |
| Priority Queue | - | O(log N) | O(log N) | 우선순위 처리 |
| Tree Map | O(log N) | O(log N) | O(log N) | 정렬된 Key |
| Hash Map | 평균 O(1) | 평균 O(1) | 평균 O(1) | 빠른 Key 검색 |
| Tree Set | O(log N) | O(log N) | O(log N) | 정렬 + 중복 제거 |
| Hash Set | 평균 O(1) | 평균 O(1) | 평균 O(1) | 빠른 존재 확인 |
| Hash Table | 평균 O(1) | 평균 O(1) | 평균 O(1) | Hash 기반 검색 |

---

# 자료 구조 선택 기준

```text
복잡한 관계 / 네트워크
→ Graph

계층 구조
→ Tree

최솟값 / 최댓값 반복 추출
→ Heap

우선순위가 높은 작업부터 처리
→ Priority Queue

Key → Value 저장
→ Map

중복 제거 / 존재 여부 확인
→ Set

빠른 Key 검색
→ Hash Table
```

# 면접 핵심 정리

```text
Q. Graph와 Tree의 차이는?

Tree는 Graph의 특수한 형태.

Tree
→ Cycle 없음
→ 모든 Node 연결
→ N개의 Node면 Edge N-1개

Graph
→ Cycle 가능
→ 연결되지 않은 Node도 가능
```

```text
Q. 인접 행렬과 인접 리스트의 차이는?

Adjacency Matrix
→ 공간 O(V²)
→ 연결 여부 O(1)
→ Dense Graph에 유리

Adjacency List
→ 공간 O(V+E)
→ Sparse Graph에 유리
```

```text
Q. BST의 검색 시간 복잡도는?

균형이 잡혀 있으면 O(log N).

하지만 한쪽으로 치우친 BST는
Linked List처럼 되어 O(N).
```

```text
Q. Heap은 정렬된 자료 구조인가?

아님.

Min Heap은
Parent <= Child

조건만 보장한다.

전체 데이터가 정렬되어 있는 것은 아니다.
```

```text
Q. Heap에서 최솟값 검색은 왜 O(1)인가?

Min Heap에서는
Root에 항상 최솟값이 있기 때문.
```

```text
Q. Heap에서 특정 값 검색은 왜 O(N)인가?

Heap은 Parent-Child 간의 대소 관계만 보장하고
전체적인 정렬 순서는 보장하지 않기 때문.
```

```text
Q. Priority Queue와 Heap의 차이?

Priority Queue
→ 우선순위에 따라 데이터를 처리하는 ADT

Heap
→ Priority Queue를 구현하는 대표적인 자료 구조
```

```text
Q. Map과 Set의 차이는?

Map
→ Key-Value 저장

Set
→ 중복 없는 Key만 저장
```

```text
Q. Hash Table의 평균 검색이 O(1)인 이유?

Hash Function을 이용해
Key가 저장될 위치를 바로 계산할 수 있기 때문.
```

```text
Q. Hash Table의 최악 검색이 O(N)인 이유?

Hash Collision이 심하게 발생하면
하나의 Bucket에 데이터가 몰릴 수 있기 때문.
```

```text
Q. Hash Table과 BST 중 무엇을 선택할까?

빠른 정확 Key 검색
→ Hash Table

정렬 / 범위 검색
→ Balanced BST
```

# 최종 요약

```text
비선형 자료 구조
────────────────────────────

Graph
→ Vertex + Edge
→ 관계 / 네트워크 표현
→ DFS, BFS

Tree
→ 계층 구조
→ Cycle 없음
→ Edge = Node - 1

Heap
→ Complete Binary Tree
→ Min / Max 빠른 접근
→ 삽입/삭제 O(log N)

Priority Queue
→ 우선순위가 높은 데이터부터 처리
→ 보통 Heap으로 구현

Map
→ Key → Value

Set
→ 중복 없는 Key 집합

Hash Table
→ Hash Function으로 위치 계산
→ 평균 검색/삽입/삭제 O(1)
```

```text
관계 정리
────────────────────────────

Tree
⊂ Graph

Heap
→ Tree의 한 종류

Priority Queue
→ Heap으로 주로 구현

Hash Map
→ Hash Table 기반 Map

Hash Set
→ Hash Table 기반 Set
```
