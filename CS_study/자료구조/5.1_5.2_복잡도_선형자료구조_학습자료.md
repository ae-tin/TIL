# 5.1 복잡도

복잡도(Complexity)는 **알고리즘이 얼마나 많은 시간과 메모리를 사용하는지 나타내는 지표**다.

주로 다음 두 가지를 본다.

```text
시간 복잡도(Time Complexity)
→ 실행 시간이 입력 크기에 따라 얼마나 증가하는가

공간 복잡도(Space Complexity)
→ 필요한 메모리 공간이 입력 크기에 따라 얼마나 증가하는가
```

알고리즘의 성능을 표현할 때 보통 **빅오 표기법(Big-O Notation)**을 사용한다.

---

# 5.1.1 시간 복잡도
## Time Complexity

입력 크기 `N`이 증가할 때 알고리즘의 **연산 횟수가 얼마나 증가하는지** 나타낸다.

실제 실행 시간을 초 단위로 측정하는 것이 아니라

```text
입력 크기 N
        ↓
연산 횟수 증가량
```

을 기준으로 판단한다.

---

## Big-O 표기법

가장 많이 사용하는 복잡도 표현 방식.

```text
O(1)
O(log N)
O(N)
O(N log N)
O(N²)
O(2^N)
O(N!)
```

성능 순서는 일반적으로

```text
빠름
 ↓

O(1)
O(log N)
O(N)
O(N log N)
O(N²)
O(2^N)
O(N!)

 ↓
느림
```

---

## O(1) : 상수 시간

입력 크기와 관계없이 연산 횟수가 일정.

```python
arr[0]
```

```text
N = 10
N = 1,000
N = 1,000,000

→ 연산 횟수 동일
```

예

- 배열 인덱스 접근
- 해시 테이블 평균 조회
- 스택 push/pop

---

## O(log N) : 로그 시간

문제 크기를 반복적으로 절반씩 줄이는 경우.

대표적으로 **이진 탐색(Binary Search)**.

```text
N
↓
N / 2
↓
N / 4
↓
N / 8
...
```

예

```text
1,000,000개의 데이터

log₂(1,000,000)
≈ 20

→ 약 20번 정도만 비교
```

---

## O(N) : 선형 시간

입력 크기만큼 순회.

```python
for x in arr:
    print(x)
```

```text
N개 데이터
→ N번 연산
```

대표 예

- 배열 전체 탐색
- 선형 탐색

---

## O(N log N)

대표적으로 효율적인 정렬 알고리즘.

```text
Merge Sort
Heap Sort
Quick Sort 평균
```

정렬 문제에서 자주 등장한다.

---

## O(N²)

이중 반복문에서 자주 발생.

```python
for i in range(N):
    for j in range(N):
        ...
```

연산 횟수

```text
N × N
= N²
```

예

- 단순한 모든 쌍 비교
- Bubble Sort
- Selection Sort
- Insertion Sort 최악의 경우

---

## O(2^N)

부분집합을 전부 탐색하는 경우 등에 등장.

```text
N개의 원소

각 원소마다
선택 / 선택하지 않음

→ 2^N
```

N이 조금만 커져도 매우 느려진다.

---

## O(N!)

모든 순열을 탐색하는 경우.

```text
N개 원소를 나열하는 모든 경우

→ N!
```

예

```text
10!
= 3,628,800
```

완전 탐색에서 매우 큰 비용.

---

# 시간 복잡도 계산 방법

## 1. 상수는 제거

```text
O(2N)
→ O(N)

O(100N)
→ O(N)
```

입력 크기가 커질수록 상수보다 증가율이 중요하기 때문.

---

## 2. 가장 큰 차수만 남김

```text
O(N² + N + 1)
→ O(N²)
```

N이 매우 커지면 `N²`이 지배적.

---

## 3. 연속된 반복문은 더하기

```python
for i in range(N):
    ...

for j in range(N):
    ...
```

```text
O(N) + O(N)
= O(2N)
= O(N)
```

---

## 4. 중첩 반복문은 곱하기

```python
for i in range(N):
    for j in range(M):
        ...
```

```text
O(N × M)
```

N과 M이 같다면

```text
O(N²)
```

---

## 5. 입력 크기를 절반씩 줄이면 log N

```python
while n > 1:
    n //= 2
```

```text
O(log N)
```

---

# 5.1.2 공간 복잡도
## Space Complexity

알고리즘이 실행되면서 **얼마나 많은 메모리를 사용하는지** 나타낸다.

예

```python
arr = [0] * n
```

N개의 데이터를 추가로 저장하므로

```text
O(N)
```

---

## O(1) 공간 복잡도

입력 크기와 관계없이 일정한 메모리만 사용.

```python
total = 0

for x in arr:
    total += x
```

추가 변수는 `total` 하나뿐.

```text
공간 복잡도
→ O(1)
```

---

## O(N) 공간 복잡도

입력 크기만큼 추가 메모리를 사용.

```python
new_arr = []

for x in arr:
    new_arr.append(x * 2)
```

```text
new_arr 크기
= N

→ O(N)
```

---

## 재귀 함수와 공간 복잡도

재귀 호출은 **Call Stack**을 사용한다.

```python
def func(n):
    if n == 0:
        return
    func(n - 1)
```

호출 깊이가 N이라면

```text
func(N)
  ↓
func(N-1)
  ↓
func(N-2)
  ↓
...
func(0)
```

스택에 N개의 함수 호출이 쌓인다.

```text
공간 복잡도
→ O(N)
```

---

# 시간과 공간의 Trade-off

시간을 줄이기 위해 메모리를 더 사용하는 경우가 많다.

예

```text
중복 계산
→ 시간 많이 사용
→ 메모리 적게 사용

결과를 저장(Memoization)
→ 메모리 더 사용
→ 시간 감소
```

대표 예

```text
Dynamic Programming
Hash Table
Caching
```

---

# 5.1.3 자료 구조에서의 시간 복잡도

자료 구조마다 연산의 시간 복잡도가 다르다.

따라서 문제에 적절한 자료 구조를 선택하는 것이 중요하다.

---

## 배열(Array)

| 연산 | 시간 복잡도 |
|---|---|
| 인덱스 접근 | O(1) |
| 검색 | O(N) |
| 맨 뒤 삽입 | O(1) 또는 Amortized O(1) |
| 중간 삽입 | O(N) |
| 중간 삭제 | O(N) |

중간 삽입/삭제가 느린 이유

```text
[1][2][3][4][5]

3 앞에 X 삽입

[1][2][X][3][4][5]

→ 뒤 원소들을 한 칸씩 이동
```

---

## 연결 리스트(Linked List)

| 연산 | 시간 복잡도 |
|---|---|
| 특정 위치 접근 | O(N) |
| 검색 | O(N) |
| 맨 앞 삽입/삭제 | O(1) |
| 위치를 알고 있을 때 삽입/삭제 | O(1) |

단, 삽입할 위치의 노드를 찾는 과정까지 포함하면

```text
O(N)
```

---

## 스택(Stack)

| 연산 | 시간 복잡도 |
|---|---|
| Push | O(1) |
| Pop | O(1) |
| Top/Peek | O(1) |
| 검색 | O(N) |

---

## 큐(Queue)

| 연산 | 시간 복잡도 |
|---|---|
| Enqueue | O(1) |
| Dequeue | O(1) |
| Front | O(1) |
| 검색 | O(N) |

---

## 해시 테이블(Hash Table)

| 연산 | 평균 | 최악 |
|---|---:|---:|
| 검색 | O(1) | O(N) |
| 삽입 | O(1) | O(N) |
| 삭제 | O(1) | O(N) |

최악의 경우는 **해시 충돌(Hash Collision)**이 심하게 발생할 때.

---

## 힙(Heap)

| 연산 | 시간 복잡도 |
|---|---|
| 최소/최대값 조회 | O(1) |
| 삽입 | O(log N) |
| 삭제 | O(log N) |
| 특정 값 검색 | O(N) |

---

# 자료 구조 복잡도 요약

| 자료 구조 | 접근 | 검색 | 삽입 | 삭제 |
|---|---:|---:|---:|---:|
| Array | O(1) | O(N) | O(N) | O(N) |
| Linked List | O(N) | O(N) | O(1)* | O(1)* |
| Stack | O(N) | O(N) | O(1) | O(1) |
| Queue | O(N) | O(N) | O(1) | O(1) |
| Hash Table | - | O(1) 평균 | O(1) 평균 | O(1) 평균 |
| Heap | - | O(N) | O(log N) | O(log N) |

```text
* Linked List는 삽입/삭제할 노드를 이미 알고 있을 경우 O(1)
```

# 5.2 선형 자료 구조

선형 자료 구조(Linear Data Structure)는 데이터를 **순서대로 나열하여 저장하는 구조**다.

```text
Data1 → Data2 → Data3 → Data4
```

대표적으로

```text
Linked List
Array
Vector
Stack
Queue
```

가 있다.

---

# 5.2.1 연결 리스트
## Linked List

각 데이터가 다음 데이터의 위치를 가리키는 방식으로 연결된 자료 구조.

하나의 노드는 보통

```text
Data
+
Pointer
```

로 구성된다.

---

## 단일 연결 리스트
### Singly Linked List

```text
┌──────┬─────┐
│ Data │ Next│
└──────┴──┬──┘
          ↓

┌──────┬─────┐
│ Data │ Next│
└──────┴──┬──┘
          ↓

┌──────┬─────┐
│ Data │NULL │
└──────┴─────┘
```

각 노드는 다음 노드의 주소만 저장한다.

---

## 이중 연결 리스트
### Doubly Linked List

```text
NULL ← [Prev | Data | Next] ↔ [Prev | Data | Next] → NULL
```

이전 노드와 다음 노드 주소를 모두 저장.

장점

- 양방향 탐색 가능
- 삭제가 편리

단점

- 포인터를 하나 더 저장하므로 메모리 사용 증가

---

## 원형 연결 리스트
### Circular Linked List

마지막 노드가 첫 번째 노드를 가리킨다.

```text
A → B → C
↑       ↓
└───────┘
```

활용

- 라운드 로빈 스케줄링
- 반복 순회 구조

---

## 연결 리스트의 삽입

예

```text
A → B → C
```

B와 C 사이에 X 삽입

```text
A → B → X → C
```

포인터만 수정하면 된다.

```text
B.next = X
X.next = C
```

따라서 위치를 알고 있다면

```text
O(1)
```

---

## 연결 리스트 특징

장점

- 삽입/삭제가 빠름
- 크기를 동적으로 조절 가능
- 연속된 메모리 공간이 필요 없음

단점

- 임의 접근(Random Access) 불가능
- 특정 위치 접근이 O(N)
- 포인터 저장을 위한 추가 메모리 필요
- 캐시 효율이 배열보다 낮음

---

# 5.2.2 배열
## Array

같은 타입의 데이터를 **연속된 메모리 공간에 저장**하는 자료 구조.

```text
Index

 0     1     2     3
 ↓     ↓     ↓     ↓

[10] [20] [30] [40]
```

---

## 배열의 가장 큰 특징
### Random Access

인덱스를 이용해 바로 접근 가능.

```python
arr[3]
```

주소 계산

```text
Base Address
+
Index × Data Size
```

따라서

```text
접근 시간
→ O(1)
```

---

## 배열 삽입

중간에 값을 넣으면 뒤 데이터를 이동해야 한다.

```text
기존

[1][2][3][4]

2 뒤에 X 삽입

[1][2][X][3][4]
```

3과 4를 오른쪽으로 이동.

```text
O(N)
```

---

## 배열 삭제

```text
[1][2][3][4]

2 삭제

[1][3][4]
```

뒤 데이터를 앞으로 이동해야 한다.

```text
O(N)
```

---

## 배열 특징

장점

- O(1) 인덱스 접근
- 메모리가 연속되어 있어 캐시 효율이 좋음
- 순회가 빠름

단점

- 중간 삽입/삭제가 느림
- 고정 크기 배열은 크기 변경이 어려움
- 연속된 메모리 공간 필요

---

# 배열 vs 연결 리스트

| 특징 | Array | Linked List |
|---|---|---|
| 메모리 | 연속 | 비연속 |
| 접근 | O(1) | O(N) |
| 검색 | O(N) | O(N) |
| 삽입/삭제 | O(N) | O(1)* |
| 캐시 효율 | 좋음 | 낮음 |
| 추가 포인터 | 없음 | 필요 |

```text
* 노드 위치를 이미 알고 있을 경우
```

핵심

```text
조회가 많다
→ Array

삽입/삭제가 많다
→ Linked List
```

단, 실제 성능은 캐시 효율 때문에 배열이 더 유리한 경우도 많다.

---

# 5.2.3 벡터
## Vector

벡터는 **크기가 동적으로 변경되는 배열(Dynamic Array)**이다.

C++의

```cpp
vector
```

Java의

```java
ArrayList
```

Python의

```python
list
```

도 개념적으로 동적 배열에 가깝다.

---

## Vector 구조

```text
Size
→ 현재 저장된 데이터 개수

Capacity
→ 현재 메모리에 저장 가능한 최대 개수
```

예

```text
size = 3
capacity = 4

[10][20][30][ ]
```

새 데이터 추가

```text
[10][20][30][40]

size = 4
capacity = 4
```

다시 추가하려면 공간이 부족하다.

```text
capacity 부족
      ↓
더 큰 메모리 생성
      ↓
기존 데이터 복사
      ↓
새 데이터 삽입
```

---

## 동적 확장

일반적으로 용량을 2배 정도 증가시킨다.

```text
4
↓
8
↓
16
↓
32
```

재할당 과정 자체는

```text
O(N)
```

이지만 매번 발생하지 않는다.

따라서 `push_back`의 평균 시간 복잡도는

```text
Amortized O(1)
```

---

## Amortized O(1)

여러 번의 연산 전체 비용을 평균내서 분석하는 방식.

예

```text
push
push
push
push
resize O(N)
push
push
push
...
```

Resize는 가끔 발생하므로 전체 연산에 분산하면

```text
평균 O(1)
```

---

## Vector 특징

장점

- 배열처럼 O(1) 인덱스 접근
- 크기를 동적으로 조절 가능
- 캐시 효율 좋음

단점

- 중간 삽입/삭제 O(N)
- Capacity 초과 시 재할당 비용 발생
- 재할당 시 기존 메모리 주소가 변경될 수 있음

---

# Array vs Vector

| 특징 | Array | Vector |
|---|---|---|
| 크기 | 고정 | 동적 |
| 인덱스 접근 | O(1) | O(1) |
| 뒤 삽입 | O(1) | Amortized O(1) |
| 중간 삽입 | O(N) | O(N) |
| 메모리 | 정확한 크기 | Capacity 여유 공간 가능 |

---

# 5.2.4 스택
## Stack

**LIFO(Last In First Out)** 구조.

```text
마지막에 들어온 데이터가
가장 먼저 나간다.
```

예

```text
Push 1
Push 2
Push 3

┌───┐
│ 3 │ ← Top
├───┤
│ 2 │
├───┤
│ 1 │
└───┘
```

Pop

```text
3 제거
```

---

## 주요 연산

### Push

데이터 삽입

```text
O(1)
```

### Pop

Top 데이터 삭제

```text
O(1)
```

### Peek / Top

Top 데이터 확인

```text
O(1)
```

---

## 스택 활용

대표적으로

- 함수 호출
- 재귀
- 괄호 검사
- Undo
- DFS
- 후위 표기법
- 문자열 뒤집기
- Monotonic Stack

---

## 함수 호출과 Stack

```python
def a():
    b()

def b():
    c()
```

실행

```text
Call Stack

c()
b()
a()
```

# 5.2.5 큐
## Queue

**FIFO(First In First Out)** 구조.

```text
먼저 들어온 데이터가
먼저 나간다.
```

예

```text
입력
```

```text
1부터 제거
```

# Python list를 Queue로 사용하면?

```python
queue = []

queue.append(1)
queue.append(2)

queue.pop(0)
```

`pop(0)`은 첫 원소를 제거한 후 나머지 원소를 이동시켜야 한다.

```text
[1][2][3][4]
 ↓ 삭제

[2][3][4]
```

따라서

```text
O(N)
```

이다.

Python에서는 Queue로

```python
collections.deque
```

를 주로 사용한다.

```python
from collections import deque

q = deque()

q.append(1)
q.popleft()
```

```text
append()
→ O(1)

popleft()
→ O(1)
```

# 원형 큐
## Circular Queue

배열의 마지막 위치 다음을 다시 처음 위치와 연결한 형태.

```text
0 → 1 → 2 → 3
↑           ↓
└───────────┘
```

고정 크기 배열을 Queue로 사용할 때 효율적.

```text
Rear가 끝에 도달
→ 처음 위치로 이동
```

Modulo 연산을 사용한다.

```text
rear = (rear + 1) % size
```

# Stack vs Queue

| 특징 | Stack | Queue |
|---|---|---|
| 처리 순서 | LIFO | FIFO |
| 삽입 | Push | Enqueue |
| 삭제 | Pop | Dequeue |
| 대표 활용 | DFS | BFS |

기억

```text
Stack
→ Last In First Out

Queue
→ First In First Out
```

# 면접 핵심 정리

```text
Q. 시간 복잡도란?

입력 크기가 증가할 때
알고리즘의 연산 횟수가 얼마나 증가하는지를 나타내는 지표.
```

```text
Q. O(N² + N)을 왜 O(N²)이라고 하나?

N이 커질수록 N² 항이 전체 연산량을 지배하기 때문.
낮은 차수와 상수는 제거한다.
```

```text
Q. Array와 Linked List의 차이?

Array
→ 연속 메모리
→ O(1) Random Access
→ 중간 삽입/삭제 O(N)

Linked List
→ 비연속 메모리
→ 접근 O(N)
→ 위치를 알고 있다면 삽입/삭제 O(1)
```

```text
Q. Vector의 push_back이 왜 O(1)인가?

Capacity가 남아 있으면 O(1).

Capacity가 부족하면
새 메모리 할당 + 전체 복사 때문에 O(N)이지만

이 작업이 가끔 발생하므로
평균적으로 Amortized O(1).
```

```text
Q. Stack과 Queue 차이?

Stack
→ LIFO

Queue
→ FIFO
```

```text
Q. Python list의 pop(0)이 느린 이유?

첫 원소를 삭제하면
뒤의 모든 원소를 한 칸씩 앞으로 이동해야 하므로 O(N).
```
